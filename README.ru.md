Комбинируемые процессы разработки для программирующих агентов: явные предварительные условия и подтверждение результата фактическими данными.

**Выбирайте навыки под задачу и опирайтесь на существующие правила проекта.** Версия 1.2.5 содержит 29 навыков и девять условных наборов, включая [миграцию](docs/project-migration.md), [производительность и наблюдаемость](docs/adoption-integration.md), уточнение требований, передачу задач, критерии качества и повторное использование проверок. Действующие решения и делегирование сохраняются без повторных согласований и реализации.

Разделяйте работу с существующей кодовой базой и создание нового проекта. Выбирайте только нужные навыки, ведите отдельные правила для фронтенда и бэкенда, определяйте способ проверки до реализации и сообщайте, что действительно было проверено.

## Особенности коллекции

- **Краткие вводные инструкции:** убраны повторы; сначала выбирается одна основная возможность, а дополнительные разделы читаются по необходимости. Действующие решения и уже прочитанные неизменённые материалы используются повторно.
- **Запуск по задаче:** девять наборов задают условия выбора этапов. Ясная локальная правка не запускает автоматически широкое исследование, сравнение моделей или нескольких агентов; оценка времени имеет отдельное условие.
- **Преемственность правил проекта:** проверяются полная исходная база кода и последующие изменения, сохраняются каталог стандартов и источники правил. Даже страницы для новых бизнес-задач наследуют шрифты, тему, компоненты и приёмы взаимодействия проекта.
- **Уважение к существующим Skills:** сначала читаются навыки проекта, включая незавершённые, и правила агентов/плагинов. Новые навыки следуют тем же стандартам; перед изменением пользовательского Skill показываются конкретные различия и запрашивается подтверждение.
- **Новые проекты:** учитывайте запрошенный язык, исследуйте поддерживаемые фреймворки и известные релевантные риски. После выбора стека пользователем выведите правила из подходящих публичных репозиториев.
- **Проверка соразмерно риску:** отдельно определяйте объём проверки, порядок TDD и сохранение артефактов. Небольшие изменения не требуют TDD автоматически; существующие тесты пользователя сохраняются.
- **Оценка времени по измерениям:** разделяйте реализацию, проверки, ревью и внешнее ожидание. Используйте фактическое время сопоставимых задач, а не универсальный множитель.
- **Дизайн из требований:** сначала определяйте поведение и критерии приёмки, затем принимайте визуальные решения с учётом реального интерфейса и контекста.
- **Ресурсы по необходимости:** дополнительные навыки, модели и агенты используются при конкретной пользе и наличии соответствующих возможностей и разрешений среды.

Это коллекция инструкций и локальных утилит. JSON-файлы процессов описывают условия и порядок, но не являются встроенным движком выполнения рабочих процессов.

## Быстрый старт

1. Выберите процесс ниже или изучите [обязанности 29 навыков](docs/skill-map.md) (на упрощённом китайском).
2. Попросите агента прочитать нужный `skills/<name>/SKILL.md` и указанные в нём ресурсы. Загружайте только возможности, необходимые для текущей задачи.
3. Чтобы подготовить полную композицию в новом каталоге за пределами этого репозитория:

```sh
python scripts/export_bundle.py --bundle existing-frontend --out ../workflow-export
```

Добавьте `--include-optional`, чтобы включить навык координации агентов. Экспорт не устанавливает навыки и не меняет настройки агентов. Существующие каталоги назначения, перенаправленные пути, устаревшие сгенерированные файлы, цели внутри репозитория и штатные каталоги установки отклоняются.

Для штатного обнаружения навыков копируйте отдельные каталоги навыков целиком только при намерении установить их и в соответствии с актуальной документацией среды. См. [совместимость с агентами](docs/agent-compatibility.md) (на английском).

## Девять процессов

| Процесс | Назначение | Основные предварительные условия |
| --- | --- | --- |
| [existing-frontend](bundles/existing-frontend.json) | Фронтенд существующего проекта | Изучение всей кодовой базы → внутренние правила → дизайн и реализация фронтенда |
| [existing-backend](bundles/existing-backend.json) | Бэкенд существующего проекта | Изучение всей кодовой базы → внутренние правила → реализация бэкенда |
| [new-frontend](bundles/new-frontend.json) | Новый фронтенд-проект с нуля | Язык/платформа → исследование вариантов → выбор пользователя → правила из примеров → внутренние правила |
| [new-backend](bundles/new-backend.json) | Новый бэкенд-проект с нуля | Язык/требования к развёртыванию → выбор стека пользователем → правила из примеров → внутренние правила |
| [fullstack](bundles/fullstack.json) | Работа с обеими сторонами | Выбор ветки для нового или существующего проекта, отдельные правила сторон и общие контракты API |
| [project-migration](bundles/project-migration.json) | Замена фреймворка, фронтенда, бэкенда или БД | Сохраняемое поведение → цель и сосуществование → бизнес-этапы → проверка и восстановление |
| [small-change](bundles/small-change.json) | Ограниченное изменение с небольшим влиянием | Меньше формальностей при сохранении условий соответствующего типа проекта |
| [debug-and-fix](bundles/debug-and-fix.json) | Воспроизводимый дефект или сбой интеграции | Выбор способа проверки до запуска воспроизведения; изучение кода и правила до исправления |
| [release](bundles/release.json) | Запрошенная интеграция, упаковка или выпуск | Подтверждения проверок, совместимости и восстановления; исправления кода возвращаются в процесс разработки |

Поле `skills` содержит полный набор навыков для экспорта, а не указание запускать их все. Этапы выбираются по условиям. Если выбран TDD, реализация выполняется в его цикле, а отдельный этап реализации пропускается. Подробные [правила композиций](docs/bundles.md) пока доступны на упрощённом китайском.

## Проверка

```sh
python scripts/build_catalog.py
python scripts/validate.py
```

Валидатор проверяет декларации, актуальность сгенерированного содержимого, точный набор ресурсов, локальные ссылки, синтаксис Python, порядок этапов и отдельные правила подготовки к распространению. Он не доказывает правильность решений агента или отсутствие уязвимостей во фреймворке.

CI для Windows/Linux проверяет исходники, автономные утилиты и воспроизводимую упаковку. В этой проверке Windows Codex обнаружил и включил все 29 установленных навыков без ошибок разбора; 154 файла совпали с исходниками. Прежние изолированные проверки Codex/Claude и 42 браузерные проверки сохраняют исходный охват. Это не проверка точности автозапуска, соблюдения правил моделью или production. См. [журнал](docs/validation.md) и [штатную загрузку](docs/agent-loading.md).

## Примеры и автоматические релизы

[Полные примеры](examples/README.md) содержат выполненный случай из этого репозитория и запросы для небольших правок, существующего бэкенда и нового фронтенда/бэкенда. Команда `python scripts/run_examples.py` воспроизводит автономные проверки в TEMP.

Отправка соответствующего версии тега публикует проверенный ZIP и SHA-256. См. [порядок публикации](docs/github-publishing.md). [Повтор штатного обнаружения](docs/agent-loading.md) использует изолированные каталоги и не меняет навыки по умолчанию. Для необязательных штатных проверок нужны реальные клиенты; для Claude также Node и официальный Agent SDK. Остальные утилиты Python используют только стандартную библиотеку.
