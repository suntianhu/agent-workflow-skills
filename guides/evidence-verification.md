# 证据与结论



| 能说的结论 | 需要的证据 |
| --- | --- |
| 格式/lint/类型/构建通过 | 对应命令、范围、退出码与实际输出 |
| 行为已局部验证 | 真实操作或符合策略的校验，明确正常/失败/恢复哪些路径 |
| 缺陷已复现并修复 | 已观察的原始症状及修复后相同触发的结果 |
| 真实云/客户端/生产验收 | 对应真实环境与身份的实际调用结果 |

实际依赖/框架执行、外部边界替身下的局部业务校验、真实浏览器/服务/数据库渠道验收分别列证据，写明版本、输入范围、替身位置和未联调边界；不能以真实核心库已执行掩盖数据库或传输仍是替身，也不能以替身通过推定真实依赖行为。密码等保存/认证改动核对适用边界与往返证据，具体执行范围沿用测试策略。

局部审查只能支持已查范围的发现，不能升级为全项目没有 bug。编译、构建工具和业务验收分开报告；某构建因私有依赖解析或离线环境失败，即使另一条编译命令通过，也须保留各自命令、结果和限制，不改写成该构建已通过。

缺陷修复还须核对受影响正常功能的证据，不能只依据原报错消失宣称相关行为保持正常。按实际调用关系列清原症状、相关正常消费者与适用失败/恢复路径各自的已验/未验范围；优先复用已有记录，无关功能不扩成全仓回归。P0 或环境受限时，静态推演不能冒充执行证据，未实测部分须保留为缺口，本阶段不绕过既定测试政策补跑。

bug 修复和小需求均须核对最终 diff：每处改动对应哪条原需求，或为何是完成它不可缺少的联动。多个条目分别核对目标、保留行为、改动位置和已验/未验范围；一项通过不能代替其他项验收。必要联动有实际依赖和影响依据，同一文件内的无关功能不因位置相近获准修改；未要求改变的其他消费者行为与契约应保持，不能只确认新增结果成功。小改可在交付中简述对应关系，不强制另建报告。

缺陷部分进一步对应根因、必要调用方调整或本次失效逻辑清理。新增业务文件须有现有结构无法合理承载的理由，修复不应遗留已失效的旧分支、重复实现或临时兜底；仍有动态调用或兼容用途的旧逻辑应有保留依据。与已列需求或必要联动无关的功能调整、格式化、改名、搬文件、依赖升级及架构重构不混入本次交付，新发现的范围外问题只列建议；无法说明对应关系的本任务增量先核实并收敛，不覆盖用户既有修改。

消费已有适用的质量门槛审查结论和规则版本，不重复审其差异；涉及门槛变化但尚无结论时只交回只读审查补该缺口。性能结论须对应可比较的基线/复测及波动，观测结论须区分已配置、实际信号可查、告警已演练和真实通知送达；本阶段不自动执行缺失测量/告警操作。

以定向清理完成后的最终交付状态核对声明。实现后证据在其目标代码和工程输入未改变时可复用；收尾改了源码、依赖/锁文件、构建或运行配置时，只补影响到的工程检查/直接验证。仅移除无关日志、trace 或仓外临时报告不使行为证据全部失效，不机械重跑全量。代理总结、编译成功、模拟页和代码推演只能支持各自范围。

浏览器证据应对应最终页面与实际断言，标明 mock/拦截、环境和身份范围；点击或录制成功不直接支持业务成功。数据库证据分别标明估算计划、实际执行、迁移准备和迁移执行，不能用管理身份结果证明普通用户隔离。核对证据不自动启动缺失的浏览器/数据库操作。

目标宿主分别记录导入、编译、打开、业务运行与真机的实际状态；IDE启动或其他宿主的预览不能递推后续成功。命令退出码同时核对结构化业务错误、实际打开的目标和产物/页面状态；退出0仍可能业务失败。

“工具未安装/不可用”等环境结论须说明已查范围：默认路径未命中时，在授权内核对PATH、用户指定位置、快捷方式或安装记录等可用线索，不扫描无关盘符或读取其他项目凭据。缺有效身份时保留待验门槛；用户已说明稍后补充就不重复索取，也不借用其他项目账号。

交付报告按任务大小简述：结果和文件、实际命令及结果、行为覆盖与回归记录、未完成外部验证/风险、实际耗时和估时偏差。轻微改动压缩到必要几句；不要虚构“全量测试通过”。
