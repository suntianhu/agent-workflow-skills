# 精准采纳与项目 Skill 协调

先用名称/描述筛选一项主要能力；只有真实缺口才补其他技能，不按关键词、概率阈值或组合目录全量加载。正文够用就执行，参考只读所需段落。同一职责由一个主流程负责；有效基线、已选栈、需求、设计及验证决定跨阶段复用。

小改在现有规则内直接实施并核对差异，不额外建方案、采纳表、估时日志或代理。复杂任务沿用已有短记录；只有选择存在实质冲突时才单独做技能采纳判断。只写需求/单页稿不启动产品全流程；正式接入保留开发门禁。

## 先协调项目已有能力

读取项目规则、规范及已配置的 Skill/代理入口和相关引用，按作用域承接；不能以外部技能的默认框架、主题、TDD或审批流程覆盖它们。冲突以当前用户和适用项目规则收敛；无法确定的行为仅暂停相关部分，继续独立工作。项目规范正文保持一个维护源。

现有 Skill 只写了一部分，也先读正文/引用和实际调用，辨别仍有效内容与缺口。优先保留或局部调整；仅当范围已失配、结构无法承接或用户明确需要时，提出合并/重建，说明旧规则和调用入口如何保留，不能把“不完整”等同可直接覆盖。

## 改动用户已有 Skill 须确认

在写文件前展示具体文件/差异、理由、保留与移除内容、冲突和调用方影响，明确是复用、局部调整、合并还是重建；获得用户对该方案的明确确认后才实施。适用于Skill自身正文、专属引用资源、薄入口、发现/代理配置与指向关系。泛泛的“优化一下”不等于确认具体改写；沉默不算确认。

只读采纳和普通业务开发继续沿用已有授权，不因使用Skill多加审批；共享规范的事实同步不得借机改变用户已定技能规则。

可先只读调查、准备仓外候选与差异，未确认时继续不依赖此变更的工作。已有针对同一具体方案的确认直接沿用；超出确认范围重新告知。确认记录写回同一项目采纳/维护记录，不复制规范，不借本集合自动安装或改全局技能。
