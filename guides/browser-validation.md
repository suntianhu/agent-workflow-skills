# 浏览器交互与业务结果核对

仅在本次需要且允许实际浏览器交互验证时读取。使用宿主已提供的浏览器能力；Playwright CLI 是可选适配，不要求安装或替换工具。不改变已有 P0/P1/P2、TDD 与保留决定；缺少运行条件时先完成独立可做的检查，再列出缺口。

执行时承接已选政策：P0 不新增或运行自动测试，保留规定工程检查；P1 允许约定范围内临时验证，不新增持久套件且保留已有用例；P2 按已授权范围维护长期用例。策略的选择和变更仍由当前项目测试约定负责，本资料不另选默认政策。

## 会话和操作范围

记录目标 URL、环境、身份类别、本次可操作数据和业务验收条件。优先使用任务专属会话及获准测试账号；使用已有会话时先确认所选标签页、路由与身份。不能因浏览器已登录就操作其他账号、真实交易或批量数据。

不复制个人浏览器凭据建立测试会话。保存登录状态、截图、网络记录或 trace 前，核对必要性、内容和保留范围；这些产物可能带有 token、Cookie、私有页面和请求包体。只交付脱敏且必要的证据，公开上传需本次授权。结束时只处理本任务创建且可清理的会话与产物，避免 close-all、kill-all 或删除用户既有 profile。

## 观察、定位和等待

1. 从当前页面快照或 DOM 确认控件及状态。跳转、重渲染或目标变化后重新检查元素引用；不能凭旧 e17 一类编号猜测当前控件。
2. 选择唯一、可解释的定位：角色和可访问名称、关联标签，或项目已有稳定测试标识。先限定表单/区域，再解决重名；没有依据不使用第几个元素或脆弱的长选择器。
3. 等待本次需要的条件，如目标可见、可用、加载状态结束或预期响应，设置有界超时。固定 sleep、重试点击或 force 不能代替条件判断。元素可点击只证明可操作，不证明业务前置条件成立。
4. 操作后重新观察结果；结果未知先查状态，涉及创建、发送或付款时尤其避免盲目重复执行。

以上是工具无关的方法。使用 Playwright 时，可用语义 locator、自动可操作性检查与重试断言实现；使用快照引用型工具时，以最新可观察引用为准。具体命令读取已安装版本帮助，不把参考资料中的 CLI 命令当作所有宿主 API。

## 结果证据

按验收条件区分输入动作、请求结果、界面反馈和必要的持久结果。例如表单：确认正确字段和身份 → 提交一次 → 观察约定反馈与错误恢复 → 通过允许的重新查询或重进页面确认业务结果。若任务只要求视觉检查，核对相应视觉结果即可，不扩成全量业务测试。

录制生成的操作代码只有动作时，需要补上本任务允许且有价值的断言，才能作为行为证据；不自动创建持久测试文件或新框架。mock、路由拦截、缓存、模拟身份和测试数据明确记录；模拟成功不能证明真实 API、真实鉴权或生产链路成功。

按直接影响选择正常、失败与恢复路径；共享布局变化才扩大相关页面、主题或屏宽。模拟移动视口只支持对应浏览器布局结论，不冒称小程序或原生客户端验收。记录环境、操作与断言、观察结果、证据位置和未测项；截图证明所见状态，不能独自证明持久化或权限正确。

例如“编译通过，点击了提交按钮，未核对成功反馈与保存结果”：可以报告构建与点击事实，业务验收仍待补证。一次工具调用成功不应升级为整条流程通过。

方法参考 Microsoft Playwright CLI 的交互、会话、录制和诊断能力，未分发其工具或命令手册。可核对官方[定位器](https://playwright.dev/docs/locators)与[可操作性检查](https://playwright.dev/docs/actionability)。
