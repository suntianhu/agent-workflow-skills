# 需求、行为与验收设计

本技能拥有需求简报与行为契约；视觉技能消费这些输入，不在这里预设配色、字体或界面模板。适用于页面、API、任务、命令行、数据迁移等需求。

## 输入与范围

从现有材料提取目标使用者或调用方、使用场景、首要任务、成功条件、真实数据来源、权限、兼容边界、不可改区域与交付物。区分事实、假设和需要用户决定的内容；只问影响正确性、范围或关键产品取舍的缺口。老项目开发前仍须完成全仓理解与内部规范；新项目可先做技术无关需求研究，选栈后补实现约束。

区分“只写需求”“先看单页设计/独立原型”和“正式实现/接入”。前两类在本次产物处停止；已给信息足够就形成简短简报，不要求先有项目、选框架或全仓理解。老项目只看稿时读取现有规则、设计和本页相关资料，未核实实现约束标为草案；正式开发仍适用完整门禁。

## 意图收敛与继续条件

目标、成功条件、范围或关键约束存在会改变交付的缺口时，先简述当前理解、依据和未决项；先查可读材料，再提问。问题相互依赖时逐轮澄清，独立的少量关键缺口可合并；给推测时允许自由纠正，不故意提供错误猜测。将“现代化”“可扩展”等抽象目标落到实际使用场景和收益，不臆测用户偏好。

以能否说明目标使用者/调用方、可观察结果、范围/保留项与非目标，并解决阻断未知来判断准备度。状态可写“已明确 / 有可逆假设 / 存在阻断未知”；约 95% 仅是主观沟通标签，不默认打分，不代替证据、统计准确率或授权。关键的方向、数据损失或不可逆边界不能靠其他已知项平均抵消。

承接明确选择和“你来决定”等范围内委托；剩余可逆实施细节按项目规则与授权推进，不重复确认。缺少必要答案时只暂停依赖部分，继续独立工作。只要访谈/方案时在该产物处停止，已授权实施时继续相应工作，不因用户确认强制停轮。

## 从触发到可观察结果

| 产物 | 行为与验收依据 |
| --- | --- |
| 页面/交互 | 谁触发、主要动作、数据与状态变化、下一步、失败/取消/重试、无权限、重复操作 |
| API/后台任务 | 调用者、输入输出、前后置条件、错误语义、幂等/并发、超时与补偿、资源归属 |
| 迁移/存量数据 | 旧/新结构与兼容、转换规则、数量/约束核对、执行前提、失败中止与恢复 |
| 命令行/工程脚本 | 参数、输出/退出码、读写范围、重复执行、无效输入及恢复 |

仅列适用状态，不为填表编造界面、支付或其他业务需求。验收描述能观察的结果，而不是“能编译”“页面高级”或与实现逐字相同的断言。

## 产出与交接

输出目标/范围、关键路径或数据流、输入输出与状态、成功与失败验收、兼容/恢复要求和未决选择。小改可在对话内简述；复杂流程写入项目既有需求/设计位置，避免额外无用文档。

存在实质方向取舍时给2–3个具体方案及推荐；用户已明确方向或已批准则继续，不反复审批。方向开放、需要探索方案或用户要求头脑风暴时，读取 brainstorming.md，先明确使用时刻、成功/非目标与约束，再定向研究、比较任务结构，必要时用流程图/线框辅助判断。

需要界面时，把简报交给设计参考研究、项目设计规范与页面 UI 设计的适用部分；已有规则直接复用。需要后端时，把行为/数据契约交给后端实现。两者都按项目内部规范实施，并在实现前选择验证策略；纯 API 不增加视觉稿。
