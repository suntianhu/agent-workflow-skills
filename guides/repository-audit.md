# 老项目：全仓理解、项目内规范、再开发

这是代码开发前置条件，不是可选建议。重新梳理当前项目全部自有代码，不只读待改模块，不凭现有README或目录名推断事实。梳理可分批，但必须全部完成后再实施产品代码、配置和工程脚本改动。

## 清点完整范围

确认仓库根、分支/提交、工作区差异、子模块、工作区包、前后端、共享库、构建插件、生成器、数据库迁移、任务/消息、CI与部署脚本。包括隐藏与未跟踪文件，不能只列Git追踪文件或默认rg可见文件。

逐项阅读全部自有文本源码、配置键/加载逻辑、脚本、工程清单和已有规范；追踪每个模块实际入口、依赖、状态/数据流、错误路径和退出/清理。测试代码若存在也属于理解范围，读取不等于运行或恢复测试。资产按元数据、用途、引用与复制规则核对；秘钥配置只核对必要键和注入方式，不输出真实值。

### 既有 Skills 与代理规则不能漏读

清点本项目真实的技能/指令/代理/插件入口，包括根与子目录 AGENTS.md、CLAUDE.md、它们引用的文档，以及实际存在的 .agents/skills、.claude/skills、skills 或其他宿主配置。不能只检索默认可见文件，也不能用固定目录名单代替实际配置追踪；确认目录用途，不把同名产品目录自动认作技能。

逐项记录来源位置、版本/提交或本地指纹、适用范围与触发、已声明/已发现/本次采纳的状态及证据。自有技能正文、引用资料、配置和钩子纳入全仓阅读；第三方技能先核对来源、许可与元数据，再按当前任务读取适用正文。外部引用、链接或插件目标单独登记，不能因位于仓库外或依赖目录内而漏记，也不自动安装或执行；相关来源不可访问时保留未核实，对影响本次开发的未知规则继续补证。

已有技能与工程规范之间的依赖、有效规则、重复职责和冲突交给同一项目规范入口，不只记在聊天或另一份新技能说明中。看到配置不等于宿主真的启用，扫描到文件不等于已理解；报告各自证据。

依赖、缓存、版本库对象、明确生成物可排除，但记录路径、类别、真实生成/安装依据和原因。不能因为目录叫build/target/dist就自动视为无自有代码；生成模板、生成器和维护脚本仍须阅读。symlink、junction、外部子模块、不可解码/过大文件、无权限内容要列为阻断/待核实，禁止静默漏掉。子模块/独立仓库不自动获得写入权限，但依赖其源码且未能理解时不能宣称完成。

辅助工具：本包 `scripts/repo_audit.py scan` 生成不含文件内容的清单；`check` 检查逐文件阅读记录是否缺失、散列是否过期、是否有新增/移除文件。它只核验记录与快照，**不证明模型真的读懂代码**；禁止批量把清单自动填成reviewed来伪造完成。手工清点同样必须留下可核对逐项记录。

## 记录真实架构

| 范围 | 必须能解释的事实 |
| --- | --- |
| 前端 | 页面/路由、组件职责、状态所有权、请求层、会话、设计token、样式作用域、资源、原生平台边界 |
| 后端 | 请求入口、中间件、业务/事务、持久化与迁移、缓存/队列/定时任务、鉴权归属、外部服务 |
| 共用工程 | 语言/运行时与版本、依赖锁、脚本真实内容、检查/构建/发布、配置注入与日志、模块间契约 |

把“现状”“要遵循的规则”“已确认例外”“历史问题/待改进”分开。代码有缺陷不能被抄成规范；不能借写规范偷偷迁移框架或重构。证据不足的关键事实继续调查，不能用猜测填完表。

## 将审计产物交给项目规范阶段

本阶段负责全仓阅读清单、模块/数据流、现状/例外和未读阻断，不重复创建另一份工程规范。将这些证据交给项目内部规范阶段；同一执行者可接着编写，但要区分两个完成条件。单独使用时，也须在业务开发前根据审计证据完成目标项目内部规范。

规范优先更新项目既有入口；没有则使用docs/engineering/PROJECT_STANDARDS.md，前后端章节独立。规范阶段负责把事实转为有证据的目录、设计、契约、安全、工程/测试及发布规则；本阶段不能把“已扫描”或“待填模板”当成文档已完成。

## 开发门禁

审计完成要求全部自有代码已阅读、排除项有依据、无关键未知/未读。产品开发还须另满足内部规范已写入且与实现一致；审计完成不自动等于可开始实现。用户要求立即开工时说明“老项目先全仓梳理和内部规范”的当前约定，继续调查；不能以紧急、改一行或轻微风险绕过。

本轮基线有效时持续核对其后全部差异，并按规范开发，行为/契约/栈变化同步更新文档。大仓库按实际规模报告梳理进度和剩余估时；上下文用尽可续读并保留清单，不能把抽样称为全仓。外部源码/权限阻断未解决时，诚实报告未完成，不先声称可安全开发。

后续新增、更新或启用技能时，先读取当前内部规范与技能采纳记录，对照新规则补查自上次基线后的配置/引用/代码差异，更新采纳与冲突结论。仅发现一个新技能不要求机械重读未变代码，但它暴露的理解缺口必须补齐；不能以启用新技能为由另起与原梳理分离的技术栈、测试或设计流程。
