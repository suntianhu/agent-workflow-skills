# 交付集成与发布准备



提交/PR 前检查当前 branch、worktree、HEAD 和最终 diff，只纳入本次文件；不重置、丢弃、暂存或提交用户无关修改。需要隔离时复用既有 worktree，不自动创建目录或安装依赖。遵守当前平台分支命名和仓库模板。

PR 描述以最终行为和验证为中心。用户要求发布时完成可独立进行的构建、产物、配置差异、备份/回滚和明确验收步骤，再处理真正缺失的账号/外部权限；不要提前停在“能不能发布”。没有授权不自动 push、合并、公开发布或操作生产。发布要求并不授权金额/对象未知的真实扣款、退款或数据删除。

目录迁移按项目规范中的映射复核真实启动/导入入口、路径调用方与运行状态；私有配置、数据及其附属文件保持匹配和可恢复。打包验收针对实际包及其导入根/启动入口，核对当前构建清单、动态模块和资源，排除工具生成的私有配置与运行资料；不能只验证工作区或把旧输出全目录装包后声称最终产物已测。

发布前核对配置差异、精确产物、兼容与迁移、备份/回滚、身份/外部服务、实际环境健康与观测。只在用户要求发布时执行这些步骤；没有权限就完成本地可审查准备，再说明具体外部门槛。

本次涉及性能预算或观测变更时消费其已有最终证据，区分可比较复测、信号实际可查与告警真实送达；发现实施/测量缺口交回相应能力，不因发布准备重复优化/埋点或越权加压、发送通知。
