# 可独立验收的任务与可恢复交接

复杂工作需要依赖排序、独立分工或跨上下文恢复时使用；明确局部修改直接执行。沿用现有计划、需求位置或用户指定跟踪器，同一任务增量维护，不覆盖其他未完成计划，不另建漂移的待办副本。当前执行者顺序工作也可采用本方法，不因此授权启动代理。

## 任务记录

先确定业务结果和验收，再按依赖拆可独立核对的单元；前置共享契约/模型可单独成项。按耦合、风险和验收能力判断粒度，不用固定文件数、时长、行数或每几项一次审批。不是每项都需横跨界面/服务/数据库，也不能先写完所有技术层才第一次集成。

多个小需求逐项保留原始目标、保留行为和验收；已明确的简单清单可直接内联使用，不因条目多就扩成重构或新增规划文档。拆分出的技术子任务须能回溯到原需求或有依据的必要联动，不能把额外建议写入待办后当作已授权需求。任务合并、换执行者或跨上下文恢复均保留同一范围。

| 字段 | 必须能回答的问题 |
| --- | --- |
| 任务/需求或保留项 ID、目标 | 要完成哪一个可观察结果，哪些既有行为必须保留？ |
| 输入基线、契约/规则 | 使用什么实际版本和已定决定？ |
| 前置依赖、下游与集成点 | 哪些已完成才可开始，何时核对跨端结果？ |
| 读写范围与执行者 | 谁独占哪些文件、生成输入、配置和数据环境？ |
| 改动对应关系 | 每处实际改动对应哪条原需求，或为何是不可缺少的联动？ |
| 完成判据与验证入口 | 怎样核对结果，哪些证据可复用、哪些仍缺？ |
| 状态、阻断与下一步 | 已实现、已验证或尚待哪些条件？ |

任务图标出可并行区间与合并点；相互依赖任务顺序进行。共享契约、模型、入口、锁文件和台账设唯一写入者，其他执行者提交请求再顺序集成。外部写入与不可逆操作按既有具体授权处理，不能把待办状态当作授权。

## 分派与回收

在上述记录上补允许命令/环境、数据/副作用范围，以及已有验证/TDD/保留决定，提供最小原始材料与规范位置。回收真实差异/版本、实际命令/环境/结果、验收覆盖、契约变化和未验证项；主执行者核对实际产物，不把代理报告当作验收。契约变化先核对影响再通知下游，同一缺口回到原责任位置修复。

## 换上下文与恢复

交接保留已定范围/授权和决定来源、同一规范/计划位置、当前任务与下一步、工作树实际差异、有效基线与检查结果、未决风险。保留仍有价值的失败结论及证据位置，压缩冗长工具输出和已替代草稿，不因任意 token 百分比丢弃约束或强制新聊天。

恢复时核对实际工作树、记录的版本和未完成项；证据仍覆盖当前输入就复用，只补变化或缺失部分。已有有效授权继续承接，不要求另补“批准文件”；没有依据的历史完成说法不能放行。仅当现有记录不足时使用本技能提供的任务模板。
