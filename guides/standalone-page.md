# 单页设计、原型与项目接入

先按用户要的交付物选择范围，不因提到“页面”就新建产品工程。仅写需求说明由需求设计完成；要看界面则交付视觉稿或可查看原型。已有说明足够时直接做，只有会影响结果的缺口才询问。

“无目标项目”指确实不属于既有产品；新需求、新文件、仓库外 HTML 或缺少书面规范都不能据此推断为无项目。只要属于老产品，即使暂不改代码，也先按 UI 设计的现有体系检查查看相关旧页面与实际组件/样式，继承原有视觉和交互；不能把只看单页稿理解为可以另起风格。

业务完全不同也保留所属项目的全局字体、颜色语义、间距、主题、图标与基础控件；没有相似业务页时从公共样式/主题/组件取得基线。可按新任务重组内容、流程和局部布局，但不能擅自更换全项目统一规则，或把局部例外扩大为全局改版。

| 本次交付 | 需要做 | 停止位置 |
| --- | --- | --- |
| 独立单页视觉稿，无目标项目 | 最小需求、目标平台/展示尺寸、内容与适用状态；参考按需，采用本页够用的颜色/字级/间距 | 交付可查看稿及状态说明，不建立项目工程、项目级 Skill 或整体设计规范 |
| 老项目先看页面稿，暂不改代码 | 查看相关现有页面/预览或截图，并读规则/技能入口、组件/样式、规范和本页业务；无书面规范仍提取既有设计，复用品牌与冻结区 | 可在全仓阅读未完成时先交连续一致的草案，标清未核实实现约束；缺关键旧视觉证据只交结构草案，不声称最终风格或开发门禁已过 |
| 独立可点/可运行原型 | 按已授权展示形式在独立产物目录制作，标明示例数据/模拟状态；编写代码或执行自动交互前定本次局部核对与保留范围 | 验证原型的展示与有限交互，不接真实鉴权/接口/数据/支付，不写目标项目配置或初始化未选框架 |
| 正式页面实现或接入项目 | 使用已选栈与实际组件/契约；新项目先选栈/范本/规范，老项目先完成本轮全仓理解与内部规范 | 按实际请求实现并交付对应证据；设计稿批准不能代替开发门禁或后端范围授权 |

## 独立设计的最小输入与输出

从当前需求提取页面服务谁、首要任务、内容/字段、主要动作、实际目标平台、品牌/参考及所需状态。用户已授权合理安排的内容可作明确假设；缺业务数据就标示例，不能编造真实服务能力。平台未指定且影响方案时只确认这个关键缺口；已授权自行安排则说明暂按何种展示平台设计，不把原型媒介写成用户已选产品栈。

确无目标项目时，本页形成足够的局部规则即可，不要求先创建 PROJECT_STANDARDS、DESIGN.md、token 工具链或宿主配置。老项目缺书面规范时从现有页面/组件/token 继承，只补本页缺失规则，不独立发明新风格；只有用户要求共用体系或正式实施需要时，才进入项目设计规范阶段。

“给我看效果”要提供实际可查看产物，如当前工具支持的视觉稿、线框或独立 HTML/CSS 预览，不能只用一份文字方案冒充界面完成。用户指定图片/设计文件时遵从格式，不擅自改为代码工程。可点原型的成功/失败反馈只是演示，必须与真实业务能力区分。

使用已有可用工具制作和预览；不为展示一个页面安装一套未选框架或自动发布外网。静态稿做视觉核对；交互原型核对实际适用的点击、表单、状态及显示范围，不默认 TDD、永久测试或跨端全矩阵。目标是小程序/原生/桌面时，浏览器稿只证明该稿效果，不冒充目标平台验收。未实际预览则如实说明。

页面稿/原型本身是用户交付物，按约定保留；P1 临时验证脚本和报告另行定向收尾，不能把交付稿当临时测试删掉。交付后停在当前范围，只有用户继续要求正式实现/接入时才转入对应项目开发流程；不得借“原型”名义修改产品代码、组件、路由、依赖、配置或真实业务状态。

若用户明确要求独立原型采用 TDD，仍在 UI 原型阶段按该交付物执行，先定适配原型的局部验证和保留范围；不因此触发组合的正式产品 TDD 阶段、端内产品实施约束或产品选栈/全仓门禁。测试须执行真实原型行为，不能用其他语言重写其逻辑制造通过。
