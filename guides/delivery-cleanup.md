# 以实际证据交付

交付前核对最终文件范围和用户已有修改，确认临时验证产物、无效入口、资源、依赖、说明是否按本次约定收敛。功能删除按引用、配置、类型、动态路径和构建复制规则确认用途，不能凭一次关键词零命中删除资源。

临时产物清理不代替业务代码收敛。缺陷修复应在实现阶段按已有修改授权，同步移除或合并本次替代后失效的旧分支、重复逻辑、临时兜底及相关引用；交付时核对最终 diff 和实际用途，遗漏项交回实现处理。旧代码原先存在不等于必须保留失效片段，但仍有动态调用、配置/平台注册或兼容用途的代码应保留并说明依据；不能把本次修复扩大为全仓死代码清理，也不能仅凭关键词零命中删除。

承接测试策略确定的项目内独立任务目录与产物清单，例如 `.codex-tmp/<task-id>/`。逐项清理本任务主动新增且明确可丢弃的验证脚本、夹具、临时编译输出、日志、临时配置和截图/trace，再移除空的任务目录；核对实际剩余文件和目录，不只报告命令已发出。不要删除共享临时根目录、其他任务内容或无关的用户原文件。已有明确授权的其他临时位置按其实际清单和权限处理，不为清理而移动到别处。

Windows 删除/移动前解析绝对路径，确认位于授权目录，检查符号链接/junction 和路径重定向；只清单式操作确认目标。使用同一 PowerShell 和 -LiteralPath，不跨 shell 拼接删除，不清空整个 target 代替定向清理。策略拒绝时停止绕行并报告真实未完成范围。

项目内路径、文件系统权限和用户的任务授权不能替代工具实际权限；不要承诺放在项目内就一定可删，也不通过改脚本语言、工具或路径规避已发生的拒绝。

TDD 结束删除只处理本任务明确不保留的新用例、专用入口/依赖和测试报告。保留用户原文件、生产转换器、正常 classes/JAR、Maven 元数据、合法运行依赖、test.env、数据库迁移和运行配置。不能用技能文档当作既有测试的批量删除授权。

按任务产物清单核对临时脚本、重试副本、项目内临时测试路径、fixtures、快照、截图/trace、测试入口和专用依赖，报告已保留/已移除/受阻三类实际状态。P1 不把临时新增静默留进长期套件；P2 保留用例须有责任模块与回归价值，按已有授权处理重复项。不能为清理方便删除整个测试根、构建输出或其他任务资料。

定向收尾之后再交接完成前证据核对。若收尾改变源码、依赖/锁文件、构建或运行入口/配置，列明哪些原证据受影响，只补相应工程检查或直接验证；仅删除不影响工程输入的仓外报告、日志或 trace 可直接复用原证据。交付原型等需保留产物不属于临时验证清理对象，不以收尾为由重开全量审查/测试。
