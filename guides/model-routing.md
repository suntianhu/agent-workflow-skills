# 模型与工具能力路由



默认使用当前会话能力。依据任务歧义、推理深度、上下文、视觉输入和实测失败决定是否建议调整；不是任务越多越要换模型。

| 情况 | 决策 |
| --- | --- |
| 文案、普通文档、明确局部代码 | 当前能力足够，不追加模型或代理 |
| 一般产品开发 | 当前模型主导；先把需求和数据流梳理清楚 |
| 多约束架构、并发安全、复杂跨层缺陷 | 有具体推理瓶颈时建议更强推理档位；先核对当前可用选项 |
| 需要看图或生成图片 | 使用真正支持该输入或产物的现有工具；文字能力不冒充视觉验证 |
| 可独立且耗时明显的工作 | 只有用户或适用规则明确授权代理时才委派；比较协调开销、冲突和收益 |

技能只能建议或调用环境已开放的能力，不能自行切换当前聊天模型；不得宣称已切换而没有工具证据。不写死模型名称、价格、排名和“默认最强”。需要具体比较时先查当前允许列表和官方文档，无法核实时给能力标准。委派应给最小原始材料、范围、产物和只读/可写边界，不把整段历史无差别转发。
