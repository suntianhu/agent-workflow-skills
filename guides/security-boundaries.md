# 应用信任边界与错误恢复

本技能独立覆盖身份、授权、隔离和输入边界；支付、图片等只是条件场景。先明确本次变更的信任入口、主体、对象、允许动作和真实环境，不默认全仓渗透或外部账号操作。

## 认证、会话与授权

- 服务端核定身份；客户端的userId、角色、owner、本地标记或隐藏按钮不能授予权限。核对登录、续期、退出、失效凭据和错误响应，不保留开发旁路解决真实鉴权问题。
- 每次对象读取、写入、确认、删除及文件签名核对主体、动作、归属和适用租户；校验替换对象编号、跨账号/角色/租户、批量查询和后台任务，不只检查入口登录。
- 会话、缓存、异步回写和服务端共享状态不得混淆账号/租户。认证/授权失败应失败关闭，保留不泄露敏感资源存在性的必要错误语义；cookie/token、跨域与CSRF等按实际认证方式和当前官方框架规范核对。

## 输入、外部请求和敏感信息

信任边界做类型、长度、允许值、内容及协议校验。文件上传核对格式/解码内容、大小、目标键和归属；服务端下载控制协议、主机、解析后的地址、重定向、响应长度与超时，防止访问不应开放的目标。

日志、包体、公开资料不包含凭据、令牌、用户内容、私图或完整签名地址。私有文件持久化必要对象键与归属，授权后短期签名；不能公开桶或扩大权限来规避失败。外部响应核对业务字段，HTTP成功不等于任务完成；重试、取消、未知结果与孤儿资源处理有界。

## 并发与恢复

重复点击防护只是前端交互。服务端根据真实风险使用幂等、唯一约束、事务/锁和状态迁移，核对重发、乱序、过期、并发与部分成功；失败可恢复，旧请求不能覆盖新主体或新操作。

## 支付退款（仅涉及时）

按项目现行渠道和官方协议核对签名、金额/币种、商户/商品/订单、用户归属及服务端状态。通知/查单/补偿幂等；未知结果查询原单，不盲目重建扣款。最终退款成功后才按规则撤对应权益，沙箱与生产隔离。

没有明确对象、金额和影响授权，不执行真实扣款、退款或业务数据删除。发布请求也不扩大这项授权；先完成本地准备和精确外部验收步骤，缺账号时列为阻断。P0不因此恢复自动测试。

输出已核实发现、触发/后果、修复与实际证据范围。静态追踪、局部校验与真实渠道验收分别报告；不能以不存在公告或编译成功保证安全。

核实具体疑似漏洞或安全控制变更时读取 security-review-evidence.md，组织调用链、反证和待核实结论。涉及真实 PostgreSQL/Supabase 角色、策略或租户隔离时另读 postgres-data.md；两份资料按场景选择，不随每次安全检查全量加载。
