# 后端开发：新旧项目分别处理

后端是API/协议适配、业务、身份与权限、持久化和后台任务；不要与运营后台页面混淆。不固定开发语言、数据库、ORM、映射工具或分层模板。

本技能消费有效基线、已选栈、范本及同一项目规范；缺口交回相应能力补齐，不重复拥有前置流程。已选 TDD 时只在循环内提供后端约束/检查，不再启动另一轮实现。

版本敏感行为、陌生接口或弃用/兼容冲突按需读 [implementation-sources.md](implementation-sources.md)，复用有效来源。本次性能调查或观测方案由对应专项负责；业务/数据/埋点实现仍在本端完成一次，不因多项技能重复编码或检查。

## 老项目后端

核对覆盖全仓的有效理解基线与内部规范，补查基线后全部差异，缺覆盖才补齐；不重读未变代码。基线包含自有入口、路由/中间件、业务、实体/转换、数据访问/迁移、缓存、消息/任务、外部调用、配置、脚本和部署。本次承接摘要/规范并读取相关代码；前端同仓也须完整覆盖，端内规范独立。

规范至少覆盖：真实模块/调用与事务边界，DTO/领域/持久模型转换，查询与分页，错误/状态码，认证和对象归属，幂等/并发，时间/ID与迁移，外部调用预算与超时，配置/密钥注入，日志/观测，运行/检查/构建/发布命令与所选测试政策。重要规则附实际实现依据；历史偏差列为例外，不以文档掩盖缺陷。

先确认现有契约与数据兼容，再按规范开发。框架/依赖已过支持期时说明真实风险和升级选项，但用户未选择迁移前不能夹带重写；本次开发仍需明确相关风险的处置边界。

修复缺陷优先在原业务、数据访问或协议适配模块的职责位置最小充分修改。新增业务文件须说明现有结构无法合理承载的依据，不以修复副本、平行服务或额外兜底绕开原错误路径；同一缺陷重试不按轮次增加业务文件。必要的版本化迁移或平台文件按现有工程约定新增，不受“优先原位”机械限制。同步移除或合并本次替代后失效的分支、重复逻辑、临时兜底及引用，先核对直接调用、动态依赖注入、任务/消息注册、配置和旧数据兼容用途；仍有用途或未证实无用的代码保留。不扩大清理历史代码，不夹带无关格式化、改名、搬文件、依赖升级或架构重构。

## 新项目后端

按用户已选语言/框架、API/数据、同步异步和部署约束实施。选择或关键证据缺失时先交回框架选型，只补当前缺口；已有有效选择不在实现阶段再推荐候选。小服务不强制微服务、CQRS、消息队列或缓存，规则由实际风险决定。

消费已有适配的固定范本与采纳表，按同一项目规范中的模块、数据库/迁移、配置、错误、身份、幂等和检查命令实施；缺规则交回对应阶段增量补齐，不重新找范本/重填规范。按锁定版本初始化并完成最小纵向链路。

## 共同工程边界

按已列需求逐项实施，保留各项未要求改变的既有行为与契约。跨服务、共享查询、转换、缓存或配置的联动须有实际依赖依据；同一文件内的无关功能也不调整。新发现的无关缺陷或改进只记录为建议，不因多任务一起做而追加；超出已授权行为的变更先明确具体范围并取得确认，范围内实施细节不重复询问。

输入在信任边界校验，身份由服务端核定，所有对象操作校验归属；权限失败与业务失败语义一致。事务、唯一约束和幂等按重复/乱序/并发设计，不能把前端禁用按钮当可靠防线。

数据库迁移有版本、旧数据策略和恢复方法，不用本地手改库代替迁移。外部请求有超时、限长、重定向/SSRF控制和重试预算；成功要核对业务结果。日志有定位信息而不记录凭据、敏感载荷或完整签名URL。

支付、退款、私有对象、文件上传、任务等仅在本次涉及才读取对应通用规则，不把某行业业务假定为所有后端的需求。工程检查、行为验证、真实外部联调与生产发布分别提供证据。

缺陷验证同时覆盖原症状、受影响的正常业务及适用失败/恢复路径。改动共享服务、转换、查询或接口时，沿实际调用关系核对相关消费者的既有正常结果及契约，按影响选择旧数据、幂等/并发或事务检查，不能只证明原异常消失。复用已有验证入口，范围限本次实际影响；P0 仅静态追踪与反例审查，未执行行为明确列为缺口。所有需求改动的最终 diff 均须逐项对应原需求或必要联动；缺陷部分对应根因、必要调用方调整或本次失效逻辑清理，不能把其他条目通过当作本项已验收。

实际使用 PostgreSQL/Supabase，且本次涉及 SQL、迁移、查询性能、连接、锁或行级权限时，读取本技能同目录资料 postgres-data.md。数据库细则在那里维护；本指南保留通用后端职责，不要求其他数据库套用这些机制。
