# 项目内部规范

把当前项目实际约束变成可执行内部文档。

## 前置条件与边界

老项目全仓未读完不能标完成；新项目框架未由用户选定不能把候选写成已选。 遵从当前用户、适用项目规则与宿主权限；不因技能存在扩大任务或外部写入授权，已有授权继续执行。

进入已有项目时读取当前项目规则与既有内部规范，承接已完成的梳理、技能采纳和验证决定。后续启用本技能也先核对这些记录；发现冲突先收敛到同一规范入口，不另起脱节流程。

## 执行

1. 优先项目现有规范入口，否则写docs/engineering/PROJECT_STANDARDS.md。
2. 前端与后端规则分别填写，附真实代码/配置或固定范本证据。
3. 分开现状、规范、例外和待改进；承接既有技能采纳与冲突表，后续启用技能接回同一规范，开发与架构变化同步更新。

## 必须得到的结果

目标项目内部规范，含范围基线、栈、目录、设计、契约、安全、命令、验证和发布。 没有证据的项目标为未核实，不补写完成结论。
