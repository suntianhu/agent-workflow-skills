# 项目内部规范

把当前项目实际约束变成可执行内部文档。

完整代码覆盖未成立不能声称基线完成；已有有效阅读记录不重复审计，现有规范只补缺失/改变规则，框架候选不冒称已选。

沿用当前项目规范、有效基线及验证决定，缺口才补。改写、合并或替换用户已有 Skill，先展示具体差异并获明确确认；已确认范围直接沿用。只使用本次获授权的工具与操作。

## 执行

1. 沿用项目规范与技能目录，缺省才用docs/engineering/PROJECT_STANDARDS.md；部分Skill优先保留/局部调整，改用户旧入口先展示差异并获明确确认，薄入口只引用同一规范。
2. 前端与后端规则分别填写，附真实代码/配置或固定范本证据。
3. 分开现状、规范、例外和待改进；承接既有技能采纳与冲突表，后续启用技能接回同一规范，开发与架构变化同步更新。

## 交付

目标项目内部规范及需要的项目级技能入口，含目录/路径证据、范围基线、栈、设计、契约、安全、原生测试命令、保留及发布；宿主发现另列证据。 未核实项如实标注。
