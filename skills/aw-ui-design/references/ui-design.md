# 从需求简报到视觉与交互呈现

本技能消费已有需求简报和项目设计规范，负责具体页面/流程的信息层级、布局、原型和反馈表现；不重复拥有需求定义、框架选择、共用设计体系或业务验收。独立调用且缺简报时，先补齐用户/场景/主任务/数据/平台/冻结区的最小输入，再设计。参考取舍交给 aw-design-reference，共用规则交给 aw-design-standards；可由同一执行者完成，不重做同一文档。

## 设计决策

1. 围绕一个主要任务组织真实内容，明确阅读顺序和动作，不为拼卡片切碎流程。
2. 依据受众、内容和既有品牌应用颜色、字级、间距、密度、图标、图片和动效。沿用内部规范与冻结区；确需新增共用规则时回写同一设计规范，页面例外保留局部，不把同一风格套给所有产品。
3. 把需求已确定的加载、空、失败、取消、重试和无权限状态转为可理解的反馈。CTA反映实际动作，错误给可执行恢复，示例数据明确标注。
4. 按实际框架/平台处理焦点、键盘、触控、安全区、缩放、资源和原生界面；浏览器规则不原样搬到原生端。
5. 设计后对照简报审视每个主要选择，删掉无用途装饰、术语和动画。重大未决方向给可审查方案；已有选择不再加审批。

## 可用性与局部核对

核对文字对比、非颜色状态提示、可见焦点、真实标签、触控空间、布局稳定、图片失败回退和减少动态效果。尺寸/单位以目标平台规则为准。只覆盖受影响的页面、主题、屏宽和状态；共享体系变化才扩大相应范围。

视觉结论需来自实际可访问环境。代码阅读不能冒充看过界面，浏览器预览不能冒充原生或生产验收；无法访问时列清复核步骤与限制。小文案/局部间距不自动启动全量截图矩阵。字体、素材与外部设计工具按实际需要和许可使用，不为调用工具更换技术栈。

交付视觉方案/原型、token与资源决定、状态呈现和实际核对范围；业务验收仍由需求/契约与对应验证证据负责。

需要具体核对排版、密度、状态与资源时，读取 ui-system.md；平台适配/迁移或需要核对平台交互时读取 design-platforms.md 的适用行。简单文字/间距变化只做直接核对，不要求生成新的设计体系或加载外部设计数据库。
