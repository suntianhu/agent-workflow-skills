# 需求驱动视觉设计

根据内容与受众推导视觉，不套统一模板。

## 前置条件与边界

先有需求和平台约束；老项目遵从已生成内部规范与冻结区。 遵从当前用户、适用项目规则与宿主权限；不因技能存在扩大任务或外部写入授权，已有授权继续执行。

进入已有项目时读取当前项目规则与既有内部规范，承接已完成的梳理、技能采纳和验证决定。后续启用本技能也先核对这些记录；发现冲突先收敛到同一规范入口，不另起脱节流程。

## 执行

1. 确定主动作、信息层级、设计token和真实内容；建立/扩展体系或核对具体设计细则时读取ui-system.md。
2. 检查状态、可读性、焦点、触控、响应式、图片回退和减少动画。
3. 以实际环境核对受影响视觉，未看过的界面不冒称验收。

## 必须得到的结果

视觉方案/原型、token、状态与实际核对范围。 没有证据的项目标为未核实，不补写完成结论。
