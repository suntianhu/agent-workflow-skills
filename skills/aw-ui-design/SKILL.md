# 需求驱动视觉设计

按实际范围交付可查看的页面/流程设计或原型。

## 前置条件与边界

属于老产品就先看旧设计并继承全局字体/样式，业务不同或缺文档不例外；无目标项目可独立设计，正式接入另按开发门禁。 遵从当前用户、适用项目规则与宿主权限；不因技能存在扩大任务或外部写入授权，已有授权继续执行。

进入已有项目时读取当前项目规则与既有内部规范，承接已完成的梳理、技能采纳和验证决定。后续启用本技能也先核对这些记录；发现冲突先收敛到同一规范入口，不另起脱节流程。

## 执行

1. 先判交付范围；老产品先查看相关旧页面/预览或截图与组件/样式，即使无书面规范也继承原设计；单页/原型按 standalone-page.md。
2. 复用可用规则，本页补够用的局部视觉/状态/原型；平台细则按需，共用变更写回实际项目规范。
3. 要求看效果时交可查看产物；老项目与旧页面对照连续性，缺关键视觉证据只交有条件草案，未预览不冒称已看。

## 必须得到的结果

符合所需格式的可查看页面/流程稿或原型、适用状态、假设/示例说明、实际核对范围与停止位置。 没有证据的项目标为未核实，不补写完成结论。

- [ui-system.md](references/ui-system.md)：需要具体核对排版、密度、状态或资源时读取；简单局部调整沿用现有规则。
- [design-platforms.md](references/design-platforms.md)：平台适配/迁移或需要核对原生导航、输入、单位与设备行为时，只读目标平台相关部分。
