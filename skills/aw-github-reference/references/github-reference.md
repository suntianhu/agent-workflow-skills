# 开源范本到本项目规范



选定框架后先核对已有固定范本、采纳表和项目规范。来源仍适配且规则已有覆盖时直接复用，只研究本次缺口或受变化影响的部分，不因进入新阶段/新需求重搜同一范本。确实缺少依据时再找少量同语言、框架、版本线与形态的公开仓库，优先维护者官方示例/脚手架和可信团队的实际项目；不照搬框架内核或巨型平台设施。

实际打开README、LICENSE、CONTRIBUTING/SECURITY（若有）、工程清单/锁文件、目录/关键代码、格式/lint/类型配置、CI、配置示例与发布说明；缺文件如实记录。核对仓库是否归档、近期发布/维护、实际可构建性与已知公告，stars只是辅助。无法查看的项目不能作为已验证规范来源。

记录仓库URL和固定commit/tag以及引用文件位置；形成“范本规则 → 采纳/调整/不采纳 → 原因 → 本项目落点”。借鉴命名、模块边界、依赖、错误、检查和发布习惯，不照搬业务、密钥、历史缺陷或与本项目无关的微服务/测试设施。复制代码/资产时遵守原许可证和署名；仅借鉴原则也保留来源。

## 交付范本证据，交接规范与实现

本技能只产出固定范本、逐项采纳表、适用限制和规范建议，交给项目规范能力生成项目内部文档及独立前后端章节。规范阶段负责明确版本/锁定策略、目录与依赖、接口/数据、错误/权限、设计、工程命令、测试选择和发布；不在范本研究阶段初始化项目。

规范完成且本次测试策略已选定后，由端内实现能力或已选TDD循环负责初始化、最小可运行链路和工程检查。实现约束包括可信官方源、核对过的确切版本与锁文件；不得让脚手架默认测试改变用户保留政策。后续开发按规范与采纳表核对，而非在此阶段先写代码。

## 检索种子，不是固定选型

下面是寻找公开规范的起点，不是跨语言推荐结果，也没有替用户选择。2026-10-18已打开列明入口；未锁定当前任务的版本或做完整依赖安全核验。每次实际选型重新核对并记录commit/tag，拒绝用此快照证明“当前最新安全”。

| 方向 | 公开入口 | 可研究内容及限制 |
| --- | --- | --- |
| React Web | [React创建应用指南](https://react.dev/learn/creating-a-react-app) | 官方对框架与从头构建的适用条件；按实际SSR/部署需求继续查选中框架 |
| Vue Web | [vuejs/create-vue](https://github.com/vuejs/create-vue) | 官方Vue脚手架的工程选项与目录生成；它不是完整业务后台范本 |
| Java/Spring | [spring-projects/spring-petclinic](https://github.com/spring-projects/spring-petclinic) | 应用结构、构建和配置的公开样例；其UI/持久化/业务不是所有服务的通用标准 |
| 支持周期 | [Node官方发布政策](https://nodejs.org/en/about/previous-releases) | 核对该运行时的支持状态；其他语言独立查官方支持政策 |
| 漏洞证据 | [GitHub仓库安全公告](https://docs.github.com/en/code-security/concepts/vulnerability-reporting-and-management/repository-security-advisories) | 与维护者公告共同核对已知相关风险；没有公告不证明无漏洞 |

用户指定Python、Go、C#、PHP、Rust或其他语言时，动态寻找该生态官方文档及同栈成熟应用，不能退回上述示例当作替代。范本缺乏维护、许可不明、无法打开或只有星数证据时换候选，不能伪造核验完成。

## 开源许可与供应链

新框架和参考项目都查LICENSE、许可证兼容、依赖来源和维护策略。选择框架不授权复制整个仓库、上传项目资料、安装第三方技能或执行仓库自带任意脚本。仅在初始化/安装已获选择授权且核对命令目的后运行对应受控步骤。

项目规范中的引用用公开URL及固定版本，避免本机路径和私有内容进入开源发布包。公开发布前额外检查日志、来源清单、示例、凭据和用户素材；整理本地开源就绪产物不等于已发布远端。
