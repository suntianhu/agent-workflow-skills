# GitHub范本采纳

提炼成熟项目的可验证工程习惯，交接本项目规范阶段。

不能只看stars、README或框架内核；不执行未知脚本、不复制许可不明实现。

沿用当前项目规范、有效基线及验证决定，缺口才补。改写、合并或替换用户已有 Skill，先展示具体差异并获明确确认；已确认范围直接沿用。只使用本次获授权的工具与操作。

## 执行

1. 先复用有效固定来源；缺口才选择一个适配范本，读取待采纳规则及许可，证据够用即停。
2. 固定commit/tag及文件位置，形成采纳/调整/不采纳及落点。
3. 拒绝无关业务和过度架构，内部规范完成后再落地。

## 交付

固定引用、范本采纳表和目标项目规范建议。 未核实项如实标注。
