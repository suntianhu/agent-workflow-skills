# GitHub范本采纳

提炼成熟项目的可验证工程习惯，交接本项目规范阶段。

## 前置条件与边界

不能只看stars、README或框架内核；不执行未知脚本、不复制许可不明实现。 遵从当前用户、适用项目规则与宿主权限；不因技能存在扩大任务或外部写入授权，已有授权继续执行。

进入已有项目时读取当前项目规则与既有内部规范，承接已完成的梳理、技能采纳和验证决定。后续启用本技能也先核对这些记录；发现冲突先收敛到同一规范入口，不另起脱节流程。

## 执行

1. 读取范本工程清单、关键代码、LICENSE、规则、CI和配置；核对维护与适配。
2. 固定commit/tag及文件位置，形成采纳/调整/不采纳及落点。
3. 拒绝无关业务和过度架构，内部规范完成后再落地。

## 必须得到的结果

固定引用、范本采纳表和目标项目规范建议。 没有证据的项目标为未核实，不补写完成结论。
