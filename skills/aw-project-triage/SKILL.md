# 项目识别与开发门禁

先区分设计稿、独立原型与正式实施，再判断项目、影响端和门禁。

## 前置条件与边界

需求/单页稿/独立展示原型可先产出；老项目正式代码/配置/脚本开发先全仓理解与规范，新产品未选栈不初始化。 遵从当前用户、适用项目规则与宿主权限；不因技能存在扩大任务或外部写入授权，已有授权继续执行。

进入已有项目时读取当前项目规则与既有内部规范，承接已完成的梳理、技能采纳和验证决定。后续启用本技能也先核对这些记录；发现冲突先收敛到同一规范入口，不另起脱节流程。

## 执行

1. 先识别交付与停止位置；属于老产品就读现有规则、技能入口及相关旧页面/组件/样式，新需求或仓库外原型不等于从零设计。
2. 正式实施再判新旧、前后端/跨端与风险；老项目全仓门禁保留，独立原型不改产品代码或真实业务。
3. 列出前置产物、仍缺决策、允许独立推进的工作；不为已有授权重复确认。

## 必须得到的结果

交付类型与停止位置、目标项目/影响端、适用门禁和下一步。 没有证据的项目标为未核实，不补写完成结论。
