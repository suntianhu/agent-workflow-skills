# 项目识别与开发门禁

确定真实项目类型、影响端、风险和本次可执行范围。

## 前置条件与边界

老项目代码/配置/脚本开发须先完成全仓梳理与项目内规范；新项目未选栈不初始化。 遵从当前用户、适用项目规则与宿主权限；不因技能存在扩大任务或外部写入授权，已有授权继续执行。

## 执行

1. 读取当前仓库规则与工作区，确认已有业务、数据和兼容负担；新页面不等于新项目。
2. 分别判断前端、后端与跨端；依据行为与信任边界分级，不按行数。
3. 列出前置产物、仍缺决策、允许独立推进的工作；不为已有授权重复确认。

## 必须得到的结果

项目类型、端/风险、前置门禁与下一步。 没有证据的项目标为未核实，不补写完成结论。
