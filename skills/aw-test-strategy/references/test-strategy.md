# 测试、TDD、工程检查和保留策略

先读取当前项目策略。选择测试范围、是否 TDD、是否持久保留是三个独立决策。TDD 是开发顺序，不意味着必须新增仓库测试；没有测试文件也不等于行为已经验证。

## 三种项目策略

| 策略 | 新增与运行 | 已有文件 |
| --- | --- | --- |
| P0 暂停测试 | 不新增、不运行自动测试，不用临时脚本或代理绕过；保留规定工程检查 | 不因本技能擅自删用户文件；仅按项目已授权清单清理 |
| P1 临时验证 | 无持久新增；默认在当前已授权本地项目内创建独立任务临时目录，使用适配目标的工具；已有相关测试可在允许范围内运行 | 保留用户已有文件，记录本任务新增产物清单，结束后定向清理并确认结果 |
| P2 持续维护 | 已获用户/项目授权时新增或复用有长期价值的测试；不扩成全量 | 持久维护有价值用例，去重和删废弃用例须有范围授权 |

先遵从目标项目和当前用户的测试约定，不从其他项目继承“暂停测试”。无约定且本次不要求长期测试资产时，新验证默认P1；已有项目的合法维护用例保留并按其P2规则使用。P1不授权批量删除旧测试。用户明确要求某个测试时，仅覆盖本次对应策略，保留其他边界。

## 按风险选择

轻微文案、普通文档、无行为位置微调：不 TDD、不新增测试、不运行行为测试，不自动截图、全主题/窄屏矩阵或跨端联调。仍按仓库要求执行受影响端工程检查；纯规范/文档不构建产品。

常规行为：仅验证正常、失败和恢复的直接路径。关键行为：加入适用的归属、幂等、重复请求、并发、数据兼容和回滚。P0 下这些用代码追踪与反例审查核对，不包装为执行过的行为验证。

工程检查指 lint、格式、类型检查、编译/构建和静态规则。先检查聚合命令内容，不能用含测试的 verify 间接恢复已禁用测试，也不能把构建通过说成接口或云服务验收。

涉及服务、配置或持久数据的行为验证，优先使用独立端口/进程、测试身份与隔离存储，承接本任务临时目录约定。用户日常服务的运营配置、口令和数据保持原状；为展示效果不改其状态，确需原环境验证时先明确范围及恢复依据。

## 测试语言、载体与目录先确定

从现行项目规范、构建清单、依赖锁和已有用例取得影响端的真实语言/运行时、测试框架、测试根及局部执行命令，优先复用现有工具链。Java 单元/集成用例按实际 JVM 框架和 Maven/Gradle 约定；前端逻辑/组件用例按现有 JS/TS 运行器，浏览器行为用项目已有且获准的浏览器工具。名称是范围示例，不自动安装 JUnit、Vitest、Jest、Playwright 或另一套框架。

临时验证不等于 Python 验证。不得另用 Python 复制 Java/前端算法、匹配源码字符串或运行替代模型后，声称真实目标逻辑、组件或 UI 已测；这类检查至多支持其明确的静态/辅助范围。既有架构或明确选定的跨语言黑盒工具确实调用真实进程/API 时，可报告对应接口证据，不能冒称 Java 单元或浏览器验收。Python 产品或 Python 工具本身仍使用适配的 Python 测试。

本次策略写清目标模块与行为、载体/命令、复用的用例、任务临时目录、允许新增的文件边界和保留决定；必要时回写同一项目规范。环境缺少原生运行条件时先报告缺口，不能以另种语言重写实现来制造通过。P1 先明确精确路径、本任务所有权与收尾方式，不覆盖旧文件；不因此改项目全局测试配置或长期留存。

## 项目内临时验证目录

默认使用当前已授权本地项目根目录下的独立任务目录，例如 `.codex-tmp/<task-id>/`；项目已有适用临时目录约定时沿用，并在其下隔离本任务。不要默认使用系统 `TEMP`/`TMP`、用户目录或项目之外的其他盘符。没有可写项目目录或项目规则禁止放置临时文件时，先明确另一个已授权位置，不自行回退系统临时目录。

本任务主动新增的验证脚本、夹具、临时编译输出、日志、临时配置和截图/trace 均放入该任务目录；原生工具需要指定临时位置时使用本次调用参数或子进程环境，不修改系统或用户全局配置。正常构建产物、用户已有测试和运行文件仍按项目既有约定处理。

开始前核对目录的解析路径、已有内容、重定向和工具授权；记录将创建的文件及保留/清理决定。已授权的验证范围内可直接创建独立任务目录，不为目录位置重复确认；文件系统可写或位置在项目内，并不保证工具策略允许删除。确需验证创建/删除权限时，只使用本任务新建的专用探针文件，不对已有或未知文件试删。

结束后按本任务清单删除明确可丢弃的文件，再清理空的任务目录并核对实际结果；不得删除共享临时根目录、其他任务目录或用户已有内容。工具拒绝清理时停止绕行，报告实际保留路径和拒绝原因，不把未清理声称为完成。

## TDD 的一次确认

- 用户已明确要求 TDD：执行授权范围，不重复确认。项目已明确禁止：默认不采用，不反复劝恢复。
- 仅凭“常规/高风险”不能自动启用。默认按既定局部验证策略直接推进；用户已选择P1或P0不再反复问。只有证据表明本次局部验证不足以控制实际风险，且改用TDD或持久测试会实质改变成本/保留政策时，简述具体缺口、价值与保留方式，一次询问是否升级。等待这项选择时继续独立调查；没有授权不先新增框架或持久用例。
- 没有实质 TDD 收益则直接选择局部核对，不向用户发形式化问题。新增测试框架、恢复套件或改变长期保留政策另需明确授权。

本阶段只记录是否采用TDD、范围和保留决定。已选TDD时将决定交给scoped-tdd能力，其统筹红绿循环并读取端内实现约束；本阶段不写用例或实现。记录中的约束应说明失败证据必须指向目标行为、不得删用户已有实现“重新红灯”；实现后补校验须如实称为回归验证。

## 防止测试堆积

在策略中约定只为真实风险写断言，不镜像实现、不为凑数量添加快照；能复用既有用例就不重复建框架。若允许临时验证，要求执行者维护本任务产物清单和脱敏证据，交付清理能力仅据此处理本任务新增且明确不保留的文件、入口、专用依赖与报告。

新增前先检索已有测试职责；同一缺陷的重试修改同一用例/载体，不按尝试次数生成 test_fix1、test_fix2 或时间戳副本。相同规则的有意义变体可参数化；不同模块按现有边界组织，避免把所有历史任务追加到一个大文件。文件/用例数量按行为覆盖与维护成本决定，不设通用行数或数量指标，不为追求“更全”滚动扩展未受影响范围。

P2 新增持久用例要有当前风险、既有覆盖不足和维护落点；复用或合并已覆盖场景优先，去重旧用例仍需已有范围授权。交付核对最终测试 diff、新增文件及依赖、临时载体/入口/报告是否按清单收敛；受限而未清理的项目明确列出，不能静默当作长期资产留下。

P1 的“无持久新增”也覆盖既有文件里的临时断言，不能靠不新建文件而把临时检查永久追加进去。需要扩展已有用例时优先在隔离副本验证；确需原位置临时修改时记录原有差异和本次增量，收尾仅撤回本任务约定的临时部分，不回退其他用户/任务改动。

本阶段不执行删除。交付阶段按已定策略核对最终diff、测试入口和必要工程检查，不自动删用户已有测试、整个target、迁移、运行依赖、生产生成代码或test.env。策略不是数据保留授权；“考虑最后删除”不能扩大为全仓删除许可。
