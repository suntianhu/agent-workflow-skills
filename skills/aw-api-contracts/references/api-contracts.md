# 实现、接口和数据边界

先追踪真实入口、调用者、状态和持久化路径。复用当前栈和有意义的抽象；不为了“现代化”换框架，不把参考项目源码、产物、数据库、进程或配置引入当前项目。

## 契约与归属

接口变更核对请求、响应、校验、枚举、分页、时间语义、错误码、旧数据和所有受影响调用方。身份由服务端会话产生，读取、确认、删除和文件签名都校验当前用户归属；不信任客户端 userId、owner、金额、状态或对象键。管理员路由前端隐藏不等于后端权限控制。

为写操作考虑重复点击、请求重发、结果未知和并发。前端同步锁只防局部双击；服务端稳定幂等键、唯一约束、事务/锁按真实风险设计。失败保留可重试输入，未知结果查询原操作，不盲目新建。跨原生弹窗或异步请求前捕获 owner/session，返回及回写再核对，防旧账号操作污染新账号。

分层和数据访问遵从该项目内部规范。协议适配、业务规则、身份/归属、事务、数据访问要有清楚边界，但具体用Controller/Service/Repository、模块化单体、领域模式或框架惯例，由实际栈和复杂度决定。不把某个ORM、DTO转换库、SQL写法、主键方案或数据库品牌变成通用硬要求。老项目先记录真实现状与明确例外，新项目依据选定框架及开源范本形成规则，再按规则实施。

数据库变更先查真实 schema 和迁移历史；明确旧数据、约束、索引、回填和回滚。生产只走该项目版本迁移，不改库“补齐”后冒称迁移已完成。客户端缓存不作为资金、权益或资源事实来源。
