# 实现、接口和数据边界

先追踪真实入口、调用者、状态和持久化路径。复用当前栈和有意义的抽象；不为了“现代化”换框架，不把参考项目源码、产物、数据库、进程或配置引入当前项目。

## 契约与归属

接口变更核对请求、响应、校验、枚举、分页、时间语义、错误码、旧数据和所有受影响调用方。身份由服务端会话产生，读取、确认、删除和文件签名都校验当前用户归属；不信任客户端 userId、owner、金额、状态或对象键。管理员路由前端隐藏不等于后端权限控制。

核对全部直接调用方不等于要求每端都改代码。兼容性的单端增加/修正可以只改该端，说明其他调用方无需变化的依据；确有受影响的消费者才同步，不为“前后端一致”制造无用途改动。

为写操作考虑重复点击、请求重发、结果未知和并发。前端同步锁只防局部双击；服务端稳定幂等键、唯一约束、事务/锁按真实风险设计。失败保留可重试输入，未知结果查询原操作，不盲目新建。跨原生弹窗或异步请求前捕获 owner/session，返回及回写再核对，防旧账号操作污染新账号。

分层和数据访问遵从该项目内部规范。协议适配、业务规则、身份/归属、事务、数据访问要有清楚边界，但具体用Controller/Service/Repository、模块化单体、领域模式或框架惯例，由实际栈和复杂度决定。不把某个ORM、DTO转换库、SQL写法、主键方案或数据库品牌变成通用硬要求。老项目先记录真实现状与明确例外，新项目依据选定框架及开源范本形成规则，再按规则实施。

数据库变更先查真实 schema 和迁移历史；明确旧数据、约束、索引、回填和回滚。生产只走该项目版本迁移，不改库“补齐”后冒称迁移已完成。客户端缓存不作为资金、权益或资源事实来源。

涉及对象定位或身份数据时，即使不改表，也要核实实际约束和相关存量数据的基数；字段名称、类型或单条读取接口不能证明唯一。按已有授权以只读、脱敏证据核对真实匹配数量，不能凭理想夹具假定历史数据没有重复。登录/加载、验证、写入和再次读取的账号、租户、业务对象与数据源须一致；更新条件不得比已验证的对象范围更宽，不能靠首条结果或默认排序选择身份。定位条件来自该项目真实契约，不固定通用主键、复合键或数据库；关键数据事实不可核实时保留缺口，不扩大真实数据操作权限。

## 涉及可维护参数时

按本次实际配置建立够用的闭环，可内联在现有契约/规范中：字段、公开/私密、维护位置、校验、存储、实际消费者、生效或重建时机、旧值兼容及验证。仅列真实消费者；不为尚未接入的服务堆空表单。

配置读取逐项对应实际键名、定义/默认值、加载位置与消费者；排查空键、拼写错误、覆盖顺序和未接入的设置，不能只看到调用了配置函数就认为开关生效。按测试政策核对开启、关闭、缺省或无效值的适用分支，并单列不受该开关影响的强制规则；模板只放占位值，不含真实秘密。

区分运行、客户端启动、构建与外部平台配置；管理端保存不等于所有端立即生效，需要同步/导出/重建的给出可用路径和状态。配置覆盖优先级须与工具真正读取的入口一致；保存、导出或同步先校验，失败不部分更新。校验、保存和外部连通是不同结果；开关、空值及清除语义按实际消费者核对。旧配置补默认值应保留既有值、版本与秘密；切换账号/租户时检查凭据绑定，明确保留、替换或清除，不能静默复用旧主体密钥。公开响应/导出采用白名单，秘密值留在授权服务端，只暴露必要状态。
