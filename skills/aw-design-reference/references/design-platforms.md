# 按目标平台设计与核对

只读取本次目标平台和迁移来源有关行。下表是调查与验收问题，不是所有平台的 API 文档或已完成验证。具体组件行为、能力和单位按项目支持版本及当前官方资料核对，不将候选入口当正文已读。

| 目标 | 优先依据 | 设计和验收重点 |
| --- | --- | --- |
| Web/运营后台 | 项目设计系统、所选组件官方文档、适用 WCAG | 真实语义与标签、键盘/焦点、缩放与重排、表格密度/筛选/批量动作、表单恢复、鼠标与触控；不靠 hover 提供唯一入口 |
| 微信小程序 | 微信官方设计/组件及实际基础库版本、项目已选组件 | 原生导航/返回/tabBar 边界、自定义导航安全区、键盘遮挡、rpx 与 px 的实际用途、授权拒绝/取消、页面切换及前后台恢复；开发者工具与真机分开核对 |
| 其他小程序/轻应用 | 对应宿主设计/组件、能力与版本规则 | 分别查支付宝、抖音等实际宿主；微信规则不是所有小程序通用事实，核对入口/返回、授权和组件限制 |
| iOS/iPadOS | Apple HIG 与所选 UIKit/SwiftUI 官方资料 | 系统导航/返回与手势、safe area/键盘、语义文字与 Dynamic Type、VoiceOver、系统外观、弹层和权限；按支持范围核对窗口/平板，不仅拉宽手机稿 |
| Android | Android Design、实际 View/Compose/Material 文档 | 返回/导航栈、系统栏/insets、窗口适配与折叠/多窗口、dp/sp 和字体缩放、TalkBack、系统主题与权限；不直接搬入 iOS 手势和控件 |
| Windows/macOS/Linux 桌面 | 对应系统设计及实际 WPF/WinUI/AppKit/Qt 等框架文档 | 窗口缩放/DPI、键盘/快捷键、焦点与默认动作、密集数据录入、菜单/右键、读屏与高对比；Fluent 或 Web 样例不证明当前桌面栈支持 |
| Flutter/React Native/uni-app/Taro 等跨端 | 项目已选框架与每个实际发布宿主的官方资料 | 共享品牌语义/内容与行为契约，分别映射导航、控件、字体/单位、权限/生命周期和输入；Web 预览不能证明原生/小程序已适配 |
| 手表/TV/车机/XR 等 | 目标设备官方规范、输入与安全约束 | 先确认真实输出和使用环境，再增加适用专篇；触控/鼠标模型不能泛化为遥控器、表冠、语音或空间输入 |

## 跨平台借鉴怎么做

先写来源假设、目标差异、可共用意图和必须替换的行为。例如借鉴网页预约卡片的信息层级，小程序继续采用其平台导航、触控和授权恢复；Android 保留品牌语义，使用其实际返回行为。桌面录入强调键盘效率，不能用“留白更多”掩盖任务步骤增加。

响应式不是只缩放：窗口或字体变大/变小时，检查阅读顺序、内容取舍、主从结构、溢出和动作可达。仅纳入实际支持的设备、窗口、主题、语言和状态；新增平台先说明适配工作，不能从一个屏幕截图宣称全端一致。

设计验收先核对任务能否完成与恢复，再核对层级、排版、反馈、资源和品牌。工程检查、视觉看到、交互跑通、辅助技术检查、真机验证分别说明范围；未拿到目标环境就留下可执行复核步骤，不写“各端已验收”。
