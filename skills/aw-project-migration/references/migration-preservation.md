# 迁移保留项：保留行为与运行职责

此表是按范围选择的调查提示，不要求项目具备每一项。旧证据、目标映射和验收组成同一条记录；“已实现”与“已验证”分开。低频功能缺少近期流量不代表可删除，未完成的旧功能也应记录实际状态而非推断行为。

## 请求接口与外部集成

区分系统接收的请求、系统调用的第三方接口、webhook/回调、消息及内部 SDK/定时拉取。沿真实调用方追踪，包含仍在使用的旧版本客户端，不能只比对 OpenAPI 或路由数量。

| 维度 | 需要保留或明确改变的内容 |
| --- | --- |
| 地址与协议 | 方法、域名/路径、版本、重定向、编码、Content-Type、上传/下载、分页/排序/过滤、实时连接 |
| 数据语义 | 必填/可选、缺失与 null、默认值、枚举、ID 类型、金额精度/单位、时间/时区、字段大小写 |
| 身份与结果 | cookie/session/token、租户与资源归属、状态码、业务错误码、错误体、权限拒绝、限流 |
| 调用行为 | 超时、重试、幂等键及有效期、事务边界、顺序、并发、缓存与重复请求的外部效果 |
| 第三方契约 | 签名原始字节、签名/验签、回调地址、白名单、证书、配额、凭据引用、重放防护 |
| 观察与退役 | 消费者、兼容窗口、旧版使用证据、告警、适配器和删除条件 |

签名回调不能先反序列化重组再假定验签结果相同；使用获授权的脱敏样本或供应商沙箱核对。影子比较优先只读请求；有支付、通知、写库、扣库存等副作用的请求不能直接复制到两个真实系统。先隔离外部效果或使用明确的无副作用替身，模拟结果不等于生产验收。

## 定时任务、队列与补偿

不仅查代码里的 cron；还查应用启动钩子、系统/容器调度、云平台配置、队列消费者、延迟任务、手工补跑脚本和数据库作业。拿不到运行配置时写明缺口。

每个任务至少记录：任务 ID/业务目的、触发来源、完整表达式与方言（字段数、秒/年字段、星期语义）、时区及夏令时、输入/输出和外部效果、执行身份、权限、并发策略、锁/租约与过期处理、超时/重试、幂等范围、漏跑/补跑、队列重投/死信、检查点、历史执行记录和告警。迁移 cron 字符串不等于保留调度语义。

执行权交接按任务或分区明确唯一有效的副作用执行者：

1. 新执行器先处于禁用或隔离副作用的验证模式，确认业务幂等键、凭据引用和目标数据已就绪。
2. 暂停旧触发源；核对正在运行的实例、已派发/延迟/重试消息和未确认工作，按计划排空或移交检查点。
3. 需要锁/租约时，明确过期旧执行者如何被拒绝继续写入，例如业务幂等约束或栅栏校验；单有进程锁不能证明跨系统不重复。
4. 记录交接时间/游标与最后完成实例，启用新执行器；按业务时间窗核对漏跑、重复、重试和必要补偿。
5. 回退前先处理新实例与其副作用，再恢复旧执行权及检查点，不能同时启用两份补跑。

明确业务效果去重如何跨进程重启、双系统和重试保持有效，不承诺调度器提供端到端 exactly-once。任务天然可并行时按业务分区/幂等范围分配执行权，不强行把全部任务串行化。长周期任务可用授权的时间推进/重放演练，并记录真实周期仍待观察。

## 前端、管理端与服务端

| 范围 | 行为与证据提示 |
| --- | --- |
| 用户前端 | 页面/路由、旧链接/分享参数、登录与会话、状态持久化、权限、加载/空/错误/提交反馈、表单校验、文件、浏览器/平台能力、适用 SEO/可访问性 |
| 管理后台 | 角色菜单与实际接口权限、批量操作、审批、筛选、数据导入导出、报表口径、操作审计、历史任务/下载记录 |
| 服务端 | 业务规则、校验顺序、事务边界、状态机、并发控制、缓存键/失效、事件、异常补偿及配置默认值 |
| 身份连续性 | 用户 ID、密码哈希算法/参数及验证能力、会话与签名密钥引用、第三方登录绑定、租户归属；决定兼容旧会话还是明确重新登录 |
| 部署与运维 | 启动入口、环境配置契约、反向代理/跨域、迁移命令、健康/就绪、日志关联、指标、告警、备份/恢复、调度/队列实例数 |

保留现有设计规范，除非已授权重设计；保留用户工作流不要求照搬旧组件结构。迁移身份时不要把密码重新哈希后当作可验证原密码，也不要把管理员页面可见当作服务端授权证明。

## 数据与文件

清点业务表/集合、关系和约束、索引、视图/触发器/存储过程、权限策略、序列/自增、软删除/归档、附件/对象存储及引用、数据保留规则。模型导出或 ORM schema 不等于完整数据库行为。

核对字段映射、稳定 ID/外键、精度/溢出、时区、排序规则/字符集、唯一性与大小写、空值/默认值、JSON/枚举、生成字段及事务隔离差异。历史记录、附件可读性和报表统计口径纳入验收；不因新模型字段不再使用就自行丢弃旧数据。具体搬迁与对账读 [migration-execution.md](migration-execution.md)。

调度限制的官方补核示例：[Kubernetes CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/)（2026-10-21 阅读并发策略、暂停、时区和创建限制）。同一 CronJob 的并发策略不覆盖其他 CronJob，暂停也不停止已启动工作；这是核对交接风险的实例，不要求项目使用 Kubernetes。
