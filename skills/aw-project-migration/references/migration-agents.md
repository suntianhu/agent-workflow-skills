# 迁移中的任务拆分与多智能体组合

只有用户或适用规则已授权委派、宿主提供真实代理工具、任务存在可独立验收的并行部分时才启动多智能体。要求“设计多智能体方案”不等于现在必须启动代理。没有工具、没有授权或协调开销更高时，当前执行者按同一任务图顺序完成；不要虚构 Task/subagent_type 或必装插件。

## 先稳定共享输入，再并行

主执行者负责迁移范围、现行规范、保留项台账、契约版本、依赖图及最终集成。调查可按独立模块并行，只读输出证据与未知项；重叠调查结果由主执行者对账。正式实现前仍需满足项目完整阅读/规范门禁，不把多个目录扫描相加称为完整理解。

每个任务按可独立验收的业务结果拆，标出读/写范围与依赖。下表是角色职责，不是固定人数；可合并角色、分批执行，不按技能数量创建代理。

| 职责 | 输入与产物 | 可独立推进条件 |
| --- | --- | --- |
| 主执行/集成 | 简报、决策、契约、DAG、共享文件与集成验证 | 掌握各任务状态，承担共享契约/配置的最终写入 |
| 现状/契约调查 | 旧代码/配置 → 保留项、调用方与任务证据 | 只读、模块范围明确，结果可合并核对 |
| 数据迁移实施 | 已确定映射/归属 → schema、转换、对账与恢复产物 | 模型/兼容约束稳定，独占迁移文件和隔离数据环境 |
| 服务端与任务实施 | 契约/数据能力 → 适配器、业务服务、任务交接 | 所需数据层已就绪，或使用明确版本的替身并标未联调 |
| 前端/管理端实施 | 路由/交互/请求契约 → 页面与消费者适配 | 契约稳定，可用替身独立开发；真实集成另有验收 |
| 独立只读审查 | 最终差异/保留项/实际证据 → 可定位缺口与反例 | 不改实现、不扩授权；已有有效审查可复用 |

任务和服务端可因写同一业务模块交给同一人，也可在所有权和契约清晰时拆开。数据库结构、生成客户端、锁文件、共享类型、入口配置、路由注册表、公共台账等设唯一写入者；其他执行者提交变更请求或独立文件，由拥有者顺序集成。不让两个代理同时对同一数据库运行变更；可用授权的隔离实例并注明与共享环境差异。

## 可调整的依赖图示例

以下为设计示例，项目可删去不适用节点，不是宿主自动执行配置：

```text
M0 旧行为/消费者/任务盘点 + 目标与保留决定
  -> M1 契约、数据映射、共存/恢复、验证策略和文件所有权
  -> M2 贯通样本（按实际依赖顺序，确认端到端可行）
  -> 按业务批次循环：
       D 兼容数据层/迁移产物 -> B 服务端与任务接入
       F 前端按固定契约并行实施（可用明确版本替身）
       D + B + F -> I 真实集成、对账、任务交接/恢复演练
       I -> R 独立只读审查及针对性修复/复核
  -> C 已授权切换与观察 -> E 满足条件后退役
```

前置关系根据业务调整：不改数据库就省略 D，只迁移数据可省略 F。F 的 mock 通过不等于 I 通过，B 的类型能编译不等于 D 的数据已迁移。计划中显式标注可并行区间、关键路径、合并点和阻断条件，不能简单写“前后端数据库同时重写”。

## 分派与回收格式

通用任务、分派与上下文恢复统一沿用 [task-planning.md](task-planning.md) 和已有等效记录。迁移任务额外关联保留项 ID、数据水位/恢复点、当前写入或任务执行权及切换状态；回收数据/外部效果和适用对账证据。契约变化由主执行者核对影响后顺序通知消费者，已有明确授权不重复问用户。

主执行者查阅真实差异和证据，顺序集成共享输入，再完成跨端检查；代理的“通过”仅是待核对报告。发现根因共享时先收敛同一责任位置，不各加一套修复。失败任务可缩小范围/重新分派，保留已验证成果，不无故重启全仓调查或丢弃用户改动。交接保存当前阶段、台账、有效基线、未决项、下一步和真实权限边界。
