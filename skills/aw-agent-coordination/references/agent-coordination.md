# 有界的多智能体协作

先检查当前环境提供的读写、shell、联网、图像、模型和代理能力；不假设某平台工具名存在。没有代理工具时由主执行者顺序完成，仍可使用同一技能。跨平台技能只使用“读取文件/运行命令/检索/委派”等能力描述，具体API按当前环境适配。

只有当前用户或适用规则授权委派，且子任务真正独立、收益大于启动与对账成本时才用代理。文案小修不自动派人；共享写文件分配独占所有权，防并行覆盖。依赖步骤、批准与外部写入保持顺序。

不按技能数量分派代理，不为每阶段新建一轮调查/审查。同一轮有价值的独立检查可合并交给一位只读执行者，已有有效结果直接消费。协调成本高于直接执行就由当前执行者完成。

复杂工作先按 [task-planning.md](task-planning.md) 确定可独立验收任务、依赖/合并点、独占所有权及统一交接字段；顺序工作也可复用。已有等效计划直接消费，不另写一份；没有分解或交接缺口就不读模板。分派只传必要原始材料，不复制全部会话或无关凭据，不以预设答案引导审查。

已有项目的分派还要给出当前项目规则、内部规范及技能采纳表的位置/有效依据，保留已选栈、冻结区、测试/保留决定和基线后的变化。接手者或后续技能先读这些记录，新的采纳/冲突结论交回同一规范入口；不让代理或新增技能另立独立工程规则。

角色可为只读仓库调查、框架研究、范围内实现、只读反例审查。审查代理不得改代码、运行未授权测试、发布或操作真实数据；实现代理只写分配文件。主执行者合并结果后查看真实文件与检查证据，对交付负责。模型与推理档位依据任务与当前允许列表，不写死昂贵模型。

跨上下文恢复使用同一任务记录，核对真实工作树与证据有效性后继续，不重置已定范围或授权。用户询问状态时简短回答再继续，不取消原目标。
