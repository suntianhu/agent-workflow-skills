# 维护技能而不叠加规则

只在反复出现、可迁移且会改变决策的工作上形成技能。本集合保持通用开源，不附带任何私有产品的业务规则、目录、数据库约定、固定技术栈、凭据或本机绝对路径。项目实际规则在运行时从目标仓库理解并写入其内部规范。单个案例导致的窄修复不能升级为所有任务通用禁令。

技能采用标准目录：SKILL.md 必含 name 和 description；name 为短小写连字符，与目录匹配；描述准确限定触发和排除相邻职责。正文保存关键决策与条件路由，长资料放本包 references。引用路径在复制后仍成立；不得把不存在的默认技能、工具或本机绝对路径作为隐藏必需依赖。

更新先记录来源、原约束、冲突和取舍。新增规则应有实际失败或清楚用户需求依据；基线未出现失败不能伪称“红转绿”。验证至少包含文件结构、frontmatter、链接、工具实际执行和边界场景。复杂行为可在授权独立评估中观察，但少量文字决策评估不证明长期效果或模型性能。

catalog.json与guides是唯一维护源，skills是独立发布目录。改目录、参考、模板或工具后在集合根运行python scripts/build_catalog.py，只同步集合内生成文件；验收差异后记录版本和实测范围。不能在单个副本悄悄修改共同规则。前后端、新老项目的差异放对应流程，不能用矛盾例外不断堆砌。

开源分发前核对LICENSE、第三方声明、引用许可和公开包扫描。可公开的来源清单只保留能力名与必要出处，不含个人用户名、本地路径、私有仓库和产品资料。创建开源就绪文件不授权创建远端仓库、推送或发布。

交付技能文件不等于安装。只有用户另行要求，才考虑写默认 skills 目录或项目发现目录。多个套装通常选择一个入口；本集合不修改已有 skills、全局配置或自动启用策略。
