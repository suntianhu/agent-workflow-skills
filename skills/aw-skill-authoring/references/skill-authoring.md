# 维护技能而不叠加规则

只在反复出现、可迁移且会改变决策的工作上形成技能。本集合保持通用开源，不附带任何私有产品的业务规则、目录、数据库约定、固定技术栈、凭据或本机绝对路径。项目实际规则在运行时从目标仓库理解并写入其内部规范。单个案例导致的窄修复不能升级为所有任务通用禁令。

技能采用标准目录：SKILL.md 必含 name 和 description；name 为短小写连字符，与目录匹配；描述准确限定触发和排除相邻职责。正文保存关键决策与条件路由，长资料放本包 references。引用路径在复制后仍成立；不得把不存在的默认技能、工具或本机绝对路径作为隐藏必需依赖。

更新先记录来源、原约束、冲突和取舍。新增规则应有实际失败或清楚用户需求依据；基线未出现失败不能伪称“红转绿”。验证至少包含文件结构、frontmatter、链接、工具实际执行和边界场景。复杂行为可在授权独立评估中观察，但少量文字决策评估不证明长期效果或模型性能。

用户已有或部分完成的 Skill 先读现状、引用与调用，优先保留有效内容；需要局部调整、合并或重建时，先展示具体差异、理由和保留/移除影响，得到用户明确确认后才改文件/资源/入口/发现配置。可先在隔离副本准备候选；泛泛优化请求不代替具体方案确认，已确认范围不重复问。

在老项目补技能时，先读取已有技能/代理配置、项目内部规范及采纳表，把新能力接回相同门禁与维护记录。通用技能不应带走该项目的私有资料；项目自身新增技能应引用既有规范而非复制出第二套相互漂移的规则。交付时说明规范落点与适用条件，不只交一个孤立 SKILL.md。

遵从目标技能仓库已有的维护源和生成约定；若有生成副本，修改真实维护源并按该项目命令同步。直接维护单个 SKILL.md 的项目就直接修改，不要求新增 catalog、guides 或构建器。此集合自身的生成命令见其 AGENTS.md，不把本仓库目录约定作为通用技能的隐藏依赖。

开源分发前核对 LICENSE、第三方声明、引用许可和公开包扫描。来源清单保留必要的公开作者/仓库标识、版权与出处，移除未获公开授权的私人身份、本机用户路径、秘密及私有项目资料。创建开源就绪文件不授权远端建库、推送或发布。

交付技能文件不等于安装。只有用户另行要求，才考虑写默认 skills 目录或项目发现目录。多个套装通常选择一个入口；默认不改其他用户/项目 Skill、全局配置或自动启用策略，确需调整时按具体方案确认执行。
