# 局部设计规则与设计体系

在需要建立/扩展设计体系，或具体核对排版、密度、状态、无障碍和资源选择时读取。沿用需求简报、目标平台及项目内部规范；简单文案或间距修改只核对直接影响，不额外生成整套体系。

## 先判断沿用和新增

记录现有品牌、token、组件、内容密度和冻结区。新页面优先复用现有体系；只把本次缺失的规则作为局部补充，说明适用组件与理由。全局规则与页面差异在项目已有规范入口中维护，不另建冲突的事实源，也不因外部设计建议覆盖既有文件。

真正需要新体系时，从主任务、受众、真实内容、阅读频率、设备和品牌推导方案。交付信息顺序、排版/颜色/间距等语义 token、组件状态及资源决定；能说明每个主要选择的用途即可，不用风格、配色或字体数量证明方案质量。

## 将规则落到实际内容

| 决策 | 需要落到的内容 |
| --- | --- |
| 密度与布局 | 以真实列数、长文本、数字和操作频率检查扫描顺序与溢出；高密度后台优先保留关键数据与动作 |
| 字体与层级 | 标题、正文、标签、金额/数据的角色与字级；中文/其他字符覆盖、回退、缩放和加载后的布局 |
| 颜色与状态 | 表面、文字、边界、主动作、焦点、禁用和错误等语义；颜色之外有可理解的状态提示 |
| 交互与动态 | 键盘/触控可达、焦点进出、明确提交反馈与减少动态效果；动效不推挤操作或妨碍阅读 |
| 资源 | 复用可用字体、图标和品牌资产；引入外部资源时说明许可、体积、加载、离线/网络与隐私条件 |

Web 采用 WCAG 2.2 AA 时，普通文字通常至少 4.5:1，符合其大字定义的文字至少 3:1，识别控件及状态所必需的非文字信息通常至少 3:1；按对应成功准则核对适用对象及例外，禁用控件不能直接按普通正文判定。iOS、Android、小程序和 Web 的单位与目标尺寸按各平台规则核对，不能把某个 px/pt/dp 或 4/8 间距节奏推广成通用要求。

筛选表格至少区分“尚无数据”和“条件无匹配”，按真实权限分别给下一步；加载、失败、无权限有自己的语义，不能都显示为空白。为异步文字、媒体、骨架替换和校验反馈安排稳定布局，保持焦点与内容可读。引入新 Web 字体时检查许可、字符子集、回退与字体显示策略，不仅凭字体名称选择。

## 交付与局部核对

交付所需的局部原型/设计说明、复用或新增的规则、适用状态及实际核对范围。按受影响的平台、主题和屏宽验证；共享 token 变更才追踪其真实调用面。代码推演、设计稿和实际页面分别标明证据，实际浏览器核对遵从既定验证与保留政策。

例如“只改浅色桌面表格筛选”：沿用品牌、字体和密度，展示筛选应用/重置、加载、无匹配及失败恢复，说明对应现有 token；不扩展到全站玻璃拟态、远程字体或所有主题重做。

本资料学习 UI UX Pro Max 的需求驱动检索与设计细则，未携带其数据库、搜索脚本、安装器、字体或素材。需要具体标准时核对官方 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)，而非把资料中的平台示例当统一数值。
