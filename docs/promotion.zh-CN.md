# Agent Workflow Skills：让 AI 接着你的项目做

[English](promotion.en.md) · [简体中文](promotion.zh-CN.md) · [GitHub](https://github.com/suntianhu/agent-workflow-skills)

**v1.3.1 · 29 个技能 · 9 套条件组合 · MIT**

**沿用已有规范，控制每次改动，用证据说明完成情况。**

现已收录至 [skills.sh](https://skills.sh/suntianhu/agent-workflow-skills)，可按分类浏览全部 29 个技能。安装方式与隐私说明见 [Skills CLI 指南](skills-sh.md)。

用 AI 维护项目时，我想把一些约定交代清楚：项目已经定下的规则怎么沿用，这次允许改到哪里，最后凭什么判断完成。

例如，在已有后台新增物料领用页，需要先找到项目原来的规范、字体、主题、公共组件和接口约定。新页面有自己的业务流程，也要融入已有产品。下一次换聊天或换执行者，已经核对过的代码基线和决定应当接得上。

我把这些约定整理成了 **Agent Workflow Skills**。当前版本包含 **29 个技能、9 套条件组合**，覆盖新旧项目前后端开发、全栈协作、小改、排障、项目迁移与发布准备。以下几处是我重点打磨的设计。

**1. 把项目已有的规则接下去。**

老项目正式实施前，核对完整代码理解和内部规范。已有基线有效时，复用它并补查全部后续差异与缺口；新增页面沿用已有字体、主题、组件和交互习惯。后续启用的技能也回到同一个规范入口，项目中已经有效的 Skill 优先复用。

**2. 每处改动都能回到具体需求。**

多个小需求分别记录目标、保留行为和验收范围。共享函数确实需要联动时，沿真实依赖核对其他调用方；修 bug 优先在原职责位置处理根因，并收敛本次替代后失效的逻辑。最终同时核对原症状和受影响的正常行为，范围外发现留作建议。

**3. 按任务选择流程和验证。**

九套组合写明阶段的触发条件，先选本次主要能力，再补必要资料。测试范围、是否采用 TDD、是否长期保留新增测试分别决定。已经成立的选型、设计和验证结论按覆盖范围复用，额外模型与代理按具体收益和授权使用。

**4. 迁移时把旧系统的去向说清楚。**

更换框架、服务端或数据库时，建立“旧证据—消费者—预期行为—目标落点—验收”的保留映射。除了页面和接口，还包括历史数据、定时任务、回调和失败恢复；任务切换要交代执行权、在途工作与重复副作用。各批次按可验收的业务能力组织。

**5. 交付结论带上证据范围。**

说明实现了什么、实际检查了什么、还有哪些缺口。项目提供按组合导出、来源追踪、结构校验和可复现打包等本地工具，便于检查技能资源与发布内容。

已有一个能具体查看的案例：在虚构的老工程“车间台账”中增加领用页，再由后续执行者增加筛选，继续沿用原 handbook 与主题。检查覆盖新功能、原工单流程和共享样式；另一个新工程也完成了后续需求。两个小型 Web 演示合计记录了 42 项行为与不变量检查，详见[实际执行记录](https://github.com/suntianhu/agent-workflow-skills/blob/main/docs/executed-workflows.md)。

## 从一个实际任务开始

| 你的任务 | 可以先看的入口 |
| --- | --- |
| 一个范围明确的小改 | [small-change](../bundles/small-change.json) |
| 在已有前端项目新增业务页 | [existing-frontend](../bundles/existing-frontend.json) |
| 规划换框架或数据库 | [迁移用法](project-migration.md) |

按任务选择组合，或直接让智能体读取所需技能目录中的 SKILL.md，再按需读取引用资料。已有项目首次正式实施需要建立有效的代码理解与内部规范；后续复用基线并核对变化。具体方式见[中文快速开始](../README.zh-CN.md#快速开始)与[使用示例](../examples/README.md)。

## 版本与证据范围

- 组合 JSON 描述阶段条件与顺序，实际执行由智能体及宿主承担。
- v1.2.7 的 Windows Codex 原生发现检查启用了全部 29 项；v1.2.8 沿用该版技能文件。原生发现不等于模型执行效果。其他宿主的已测与文档适配范围见[兼容性](agent-compatibility.md)。
- 上述 42 项检查来自历史的两个小型虚构 Web 演示，不能据此推断当前全部技能的效果、生产迁移成绩或通用提效比例。详见[验证记录](validation.md)。

欢迎用一个脱敏任务反馈：采用了哪些能力、既有规则是否沿用、哪里出现重复，以及实际检查覆盖了什么。
