## 中文社区长版

### 标题

给 AI 编程补上项目规范和设计流程：26 个可组合 Skills

### 正文

用 AI 维护项目时，我希望它知道：这是新项目还是老项目？团队已有的规范和 Skills 是什么？设计参考从哪里来、哪些能借鉴？交付时说“完成”，实际验证了什么？

我把这些要求整理成 **Agent Workflow Skills**。**1.4.0 源码提供 26 个技能、8 套组合**，涵盖需求、头脑风暴、工程范本、设计参考、项目规范、前后端实现、排障、审查与交付。

主要约定是：

- 老项目先理解自有代码、现有 Skills 和代理/插件规则，再补有真实依据的项目规范；后来启用技能也沿用同一入口、技术栈与冻结区。
- 新项目尊重指定语言，核查候选并承接用户选择，再从匹配的 GitHub 工程提炼代码规范。
- 设计串起“需求探索→参考采纳→整体设计规范→页面/流程”，覆盖 Web、后台、小程序、原生 App、桌面和跨端。品牌语义可共用，平台导航、控件、单位和输入分别适配。
- 参考先看项目与平台官方规则，再看成熟系统、真实流程与图库。记录真正读到、看到和操作到什么，说明采用、调整与不采用的原因；好看截图不等于体验有效或素材可用。
- 设计规范沿用原有 DESIGN.md、token 和组件源，由同一项目规范入口引用；项目规范 Skill 只建薄入口，不平行复制另一套规则。
- 验证范围、TDD 与测试保留分别决定，使用真实目标的工具链；临时用例不按修复次数堆文件，Python 镜像实现不当作 Java/前端功能证据。
- 交付说明实际检查范围。浏览器、小程序开发工具、模拟器和真机分别留证，纯 API 和局部小改走适用分支。

来源账本覆盖 **11 个上游仓库、54 个选定文件**，包含许可与 NOTICE，记录固定提交、散列、阅读范围和取舍。本版在 UI UX Pro Max 等原有资料基础上，补读 **Impeccable、wshobson/agents** 的选定设计方法及 **obra/superpowers** 的头脑风暴材料，并单列官方设计网站的访问证据和未核实项。这不是整仓审计，也不代表获得上游背书。

项目有六语 README，详细技能目前主要是中文。原创内容采用 MIT；第三方许可分别记录，没有打包外部技能正文、数据库、工具或素材。

结构校验、组合导出和合成场景检查不等于真实产品验证。Codex 与 Claude 的原生发现记录属于 1.2.0 的 24 项技能，本版 26 项尚未重跑；不承诺固定提效比例或所有宿主端到端兼容。

欢迎用一个真实任务反馈：触发了什么、哪些规则有帮助、哪里重复、实际缺什么证据。公开案例先脱敏。
