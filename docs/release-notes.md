# v1.2.7 — Keep bug fixes and small requirements within scope

29 skills and nine conditional compositions. This release strengthens scope boundaries in six existing skill entries and their guides and shared task templates. Skill identities, discovery descriptions, compositions and utility scripts remain unchanged.

## Changes

- Keep each requested item tied to its original goal, preserved behavior and acceptance; splitting or combining small tasks does not expand authorization.
- Require every edit to map to a requested item or a necessary dependency with evidence. Other files can carry necessary changes, while unrelated functions in the same file remain outside scope.
- Record newly found unrelated defects, technical debt and improvements without silently fixing them. Explain blocking dependencies and confirm behavior changes beyond existing authorization.
- Check the final diff and acceptance evidence per item, preserving existing user changes and test policies. Clear local edits stay lightweight and do not gain mandatory planning or approval stages.
- Synchronize the six-language README and release metadata, preserve existing public tags, and record actual local installation and native discovery separately from model execution.

## Evidence and limits

Release preparation checks generated freshness, source structure, local links, offline utilities and reproducible tracked-source packaging. Windows/Linux CI checks the final PR before merge. Actual installation, native metadata discovery and static boundary-review evidence are recorded in validation; remote merge, tag and archive results are verified after each operation.

Installation and native metadata discovery do not establish automatic trigger accuracy, model adherence or product behavior. No model tasks, product migrations, performance benchmarks or telemetry pipelines are claimed. Historical discovery and browser checks retain their original versions and scope.
