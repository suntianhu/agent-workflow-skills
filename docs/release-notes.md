# v1.3.4 — Consumer compatibility and asynchronous session boundaries

29 skills and nine conditional compositions.

## Changes

- Trace dependency upgrades and replacements to real consumers and their synchronous, asynchronous, callback, parsing, serialization and error contracts. Select meaningful boundaries and preserve verified safety limits.
- Bind identity before asynchronous dispatch and recheck it at the final cache, UI or side-effect commit. Isolate pending work and invalidation state, reject stale results and preserve current-session recovery.
- Maintain session rules in one source guide with conditional API/frontend references. Distinguish actual application/database/HTTP checks from external substitutes, real cloud, device and production evidence.
- Classify findings as introduced, preexisting or unconfirmed without expanding repairs beyond the authorized scope.

## Scope

The catalog and source guides generate portable skill entries and references. No new skill, composition, persistent test suite or utility behavior is introduced. Existing project gates, validation policies and task-owned cleanup rules remain in force. Text scenario review is separate from actual model execution evidence.
