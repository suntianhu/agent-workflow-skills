# v1.3.2 — Preserve intent across edits, execution and delivery

29 skills and nine conditional compositions. This patch reconciles authorized installed edits with the maintenance sources and refines existing responsibilities using anonymized real development feedback.

## Changes

- Keep development-process journals out of skills and their references. Explain actual results in the current reply; preserve reusable standards and explicitly authorized records.
- Preserve content and visual anchors during local UI changes. Distinguish styling references, existing workflow reuse and new capabilities; recheck the running artifact when feedback says a change is absent.
- Trace deletion, restoration and statistics across authoritative data, snapshots, caches and synchronization. Check retained history instead of clearing unrelated state.
- Map AI modification requests to concrete authorized operations and verified results, with ownership, failure and unknown outcomes handled by the server.
- Integrate overlapping tasks into the same implementation. Summarize applicable deployment/configuration changes from the user's undeployed baseline without automatically publishing.
- Separate content versions, production batches and platform submission states; reconcile installed edits before an upgrade instead of silently overwriting them.

## Evidence and limits

The [validation record](validation.md) distinguishes manual real-case/counterexample review, source/generated checks, offline utility examples, native Codex discovery and remote release verification. Manual review and native discovery do not prove automatic triggering, model adherence or product acceptance.

No skill, composition, persistent test suite or product-specific rule is added. Existing project gates, authorization, P0/P1/P2 policies, tool behavior, licenses and historical evidence remain in force. User desktop/background preferences are inherited from the task; the patch grants no new desktop or external-data access.
