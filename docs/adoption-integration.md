项目规范已存在时补变化，不整份重填；任务和验证记录已有等效结构就复用。两个新增技能只在有对应目标/症状/信号缺口时介入，不成为普通开发的必跑流程。

## 两项新能力

- [aw-performance-optimization](../skills/aw-performance-optimization/SKILL.md)：目标/症状 → 可比较基线 → 瓶颈假设 → 唯一实现循环 → 匹配条件复测 → 保留/撤回决定。没有基线、受噪声影响或正确性证据不足时，不宣称提升。
- [aw-observability](../skills/aw-observability/SKILL.md)：运行问题 → 现有信号/缺口 → 字段/关联/查询与成本边界 → 唯一实现循环 → 实际输出与适用告警验收。配置存在、模拟通知、真实渠道送达分别陈述。

普通功能不自动埋点或优化，不默认安装分析器、采集 SDK、外部服务或额外测试框架。真实加压、数据外传、故障演练、通知/发布均按已有具体授权处理；已经明确的决定不重复确认。

## 条件组合如何复用

九个组合保持不变。八个开发/排障/迁移组合增加性能与观测的条件阶段：

1. 保留对应项目理解、规范和同一次验证策略；专项前置只补方案/基线或信号缺口。
2. 优化/埋点并入现有唯一的端内实现或已选 TDD 循环；后者选中时仍跳过独立实现阶段。
3. 专项后置只补覆盖最终产物的比较/信号证据；结果有效就跳过，不能再次编码或重开访谈。
4. 只读审查一次处理本批反例和门槛变化，修复后定向复核；完成前证据只核对声明。

只要调查/方案时不进入产品实现。纯发布组合消费既有专项结论，发现实施缺口交回相应能力，不因为发布再加压、埋点或发告警。组合 JSON 是文档条件，不是原生执行引擎；导出能力闭包也不代表全部加载。
