# 26 项技能触发与衔接审计

历史 1.3/1.4 标识属于未发布开发检查点；当前版本和真实标签以[版本记录](versioning.md)为准，旧验证证据不改写为新版本测试。

后续已在两个可运行虚构 Web 工程中实际完成新/老项目及续接需求，见[实际执行记录](executed-workflows.md)。下文保留本次静态审计时的范围，不以原来的只读场景替代后续代码、构建与浏览器证据。

版本 1.4.2，日期 2026-10-19；基线为 1.4.1 提交 `0c9510024eefa51a17de2f4766efd7a1fc5adf70`。本文件记录集合维护审计；日常任务仍只选实际适用技能，不要求执行全部行。

三组独立只读审查分别覆盖 10 项项目/设计技能、9 项实现/验证技能、7 项资源/交付技能，合计 26 项；核对 catalog、完整入口、职责指南/模板和八组合交接。共享参考以维护源和发行副本逐字节一致为据，副本服务独立分发，不构成第二轮工作。

## 六处修正

| 问题与触发例 | 修正后的判断 | 维护位置 |
| --- | --- | --- |
| 完整可核对基线仍被“本轮”限定，新需求/换聊天可能重新全读 | 基线按真实覆盖和全部差异核验；阅读缺口、规范缺口分别判断，已读但规范待补就只补规范；仅有口头“已读”仍不能放行 | project-mode、repository-audit、audit-tool、project-standards、工程模板；existing-audit-needed / existing-standards-needed |
| 新产品身份同时触发重选框架、重搜范本、重填规范，端内实现又重述前置流程 | new-stack-needed / new-reference-needed / new-standards-needed 分别检查产物缺口，已有有效选择/依据/规则直接承接；前后端只消费前置产物 | 四个新项目分支组合、framework-selection、github-reference、frontend/backend |
| 契约门禁“不能只改一端”扩大兼容性单端变更 | 覆盖所有受影响调用方；兼容性服务端变更允许仅修改服务端，保留其他端无需变化的依据 | aw-api-contracts 与 api-contracts |
| 通用技能编写强制要求本集合的 catalog/guides/build_catalog | 按目标项目实际维护源与工具；直接维护单个 SKILL.md 就直接修改，不创建不存在的构建结构 | skill-authoring |
| 开源规则把所有图片和用户名列为删除对象 | 拟分发副本仅排除/脱敏确认私密材料，保留获许可公开图片、必要作者/仓库标识和版权许可；不删除原项目文件 | open-source-readiness、skill-authoring |
| 先核对证据，再撤临时依赖/配置，可能以收尾前绿灯交付 | 八组合先定向收尾，再核对最终证据；工程输入变化只补受影响检查，删无关日志复用证据 | delivery-cleanup、evidence-verification、各 verify-deliver |

这里修正的是文本路由、职责和阶段次序，不表示旧执行者必然全部误走，也不将少量场景判断称为测得效率提升。

## 全部技能的触发与停止位置

| 技能 | 实际触发/输入 | 主产物与衔接；不重复的职责 |
| --- | --- | --- |
| aw-project-triage | 需识别交付物、目标项目、影响端或门禁 | 选范围与停止位置；纯设计/调查可先行，正式实施需完整有效基线 |
| aw-skill-selection | 多项候选或用户点名技能 | 最少适用能力与采纳决定，沿用同一项目记录；不加载全部集合 |
| aw-model-routing | 当前能力有具体瓶颈 | 核对可用资源；不自动换模型/开代理 |
| aw-effort-estimation | 请求估时或确需更新范围 | 有证据的剩余范围与未知等待；已测时间不重复校准 |
| aw-repository-audit | 老项目正式实施缺完整理解覆盖或差异未补齐 | 全仓/差异阅读证据与真实阻断；规范写作交下一责任，不重读有效未变记录 |
| aw-project-standards | 阅读成立或已选栈后，项目规范存在真实缺口 | 同一入口、分端规则和需要的薄 Skill 引用；不重做审计或重填有效规范 |
| aw-framework-selection | 新产品正式实施缺选择或关键约束证据 | 候选/核验和已选结果；用户已选不再询问，不初始化工程 |
| aw-github-reference | 已选栈但适用规则缺固定来源 | 引用/采纳表交规范阶段；有效来源复用，不先写产品代码 |
| aw-requirements-design | 目标、行为或验收尚需明确 | 最小简报/状态/契约；只在有方向取舍时头脑风暴，按 UI 或非 UI 交接 |
| aw-design-reference | 本次设计问题确需参考或用户要求借鉴 | 已读/已看/已操作及采纳证据；老产品先看旧设计，不用图库重设全局风格 |
| aw-design-standards | 明确要求共用规范，或实施有共享规则缺口 | 同一设计维护源、token/组件/平台映射；单页缺文档不自动建设体系 |
| aw-ui-design | 具体页面/流程稿或隔离展示原型 | 可查看稿与实际核对范围；老产品继承字体/主题/基础组件，正式接入另走开发门禁 |
| aw-frontend-implementation | 门禁满足后的真实前端实施 | 按已有栈/规范实现并检查；TDD 时只提供循环内约束，不第二次实现 |
| aw-backend-implementation | 门禁满足后的真实服务/数据实施 | 同上，落实业务/数据边界；不重复选栈、范本或全仓阅读 |
| aw-api-contracts | 请求/响应/数据语义等实际变化 | 追直接调用方和兼容依据；不强制修改未受影响端 |
| aw-security-boundaries | 具体信任边界变化或疑似安全发现 | 有证据的控制/发现与缺口；不自动扩大到全仓渗透、真实交易或修复 |
| aw-test-strategy | 写代码或执行行为核对前 | 同一次范围/TDD/保留决定；沿用 P0/P1/P2，风险变化更新，不重复问 |
| aw-scoped-tdd | 正式产品 TDD 已选且范围获授权 | 红绿重构统筹目标实现，端技能为约束；只保留约定测试，不重选策略 |
| aw-evidence-debugging | 故障/失败检查需调查 | 静态调查可先行，复现先有策略；只定位则交根因停止，授权修复才衔接实施 |
| aw-adversarial-review | 明确请求审查或缺覆盖最终产物的有效审查 | 只读发现交实现者；不跑未授权测试，不替实现者修复，变更后只定向复核 |
| aw-evidence-verification | 交付/通过/修复等声明前 | 核对收尾后最终状态及仍有效证据；缺证据按具体影响补，不代替整轮测试 |
| aw-delivery-cleanup | 交付前存在已确认可收尾资产 | 按任务清单收尾并交最终核对；保留原型、已有测试和运行产物 |
| aw-release-readiness | 用户请求提交/集成/打包/部署/发布 | 准备真实可审查产物与恢复门槛；代码修复交相应开发流程后返回，不重复已成立阶段 |
| aw-agent-coordination | 有委派授权且子任务独立有收益 | 文件所有权、最小材料及状态交接；主执行者核对实际结果，缺代理可顺序完成 |
| aw-skill-authoring | 可复用技能创建/修订 | 目标项目原生维护方式、结构与真实边界验证；不隐含安装或专属生成器 |
| aw-open-source-readiness | 明确需要公开分发 | 合法资产/许可/隐私与可审阅副本；内部部署跳过，不自动操作远端 |

## 新需求与后续技能共用的状态

沿用项目已有规范、采纳表及任务交接记录，携带目标仓库/范围、可核对的完整基线与全部差异、选定栈、全局字体/设计与冻结区、已定需求、验证/保留决定、实际证据及未决项。按需要补现有记录，不要求创建新的状态文件或每阶段重复写报告。

新需求和晚启技能先消费这些决定：只补变化/理解缺口，冲突写回同一入口。业务全新、无 DESIGN.md 或仓外原型也不解除所属老项目的全局视觉规则。已有选择、有效范本、规范和覆盖最终产物的审查可直接传递；新增差异使受影响证据失效时才定向更新，不回到流程起点。

## 场景与实测范围

前向只读走查覆盖：可核对基线后的新需求/换聊天、阅读完成仅规范待补、只有口头已读且隐藏文件未知、新产品全部前置有效、老产品新业务原型、兼容单端契约、跨端 TDD/P1、P0 只定位、收尾改变工程输入、只删 trace、合法公开图像与私人会话混合、内部部署复用既有审查、发布中发现代码修复的交接。

另做一次真实但隔离的技能维护夹具：独立目录仅有规则文件与单个 SKILL.md；执行者实际只收窄 description，name/正文未变，未新增 catalog、生成器、配置或安装。它证明该小夹具可直接维护，不证明所有宿主自动发现或真实产品开发通过。

结构、八组合精确导出、阶段隔离/最终次序、六语 README、实际夹具差异及离线工具结果分别见 [workflow-checks.json](../provenance/workflow-checks.json) 与 [offline-examples-1.4.2.json](../provenance/offline-examples-1.4.2.json)。自然语言条件由只读场景判断，组合仍不是可执行工作流引擎。本轮没有渲染真实产品、运行 Java/前端业务、执行真实部署或重跑原生宿主发现，来源账本也未新增研究。
