## 重复、阻断和实际遇到的问题

首轮的新栈、规范与测试决定被后续需求直接消费。UI 设计和正式实现形成同一份交付代码，没有另造原型后重做；未选择 TDD，未运行第二个实现循环。换执行者时复用基线并补读相关代码，未重新建立规范。行为发生变化时只验证增量与直接影响，前轮未变证据按指纹复用。阶段动作是实际执行记录，不是自动路由引擎计数。

实际遇到的三类问题均单列记录：

1. 新工程公开范本获取遇到限流、TLS/编码和超时，改用固定来源读取后继续；未读到的上游构建/公告等范围明确保留缺口，没有反复选栈。
2. 新演示静态服务的根路径比较问题在启动前代码审查中修正；没有包装成执行过的 TDD 红绿过程。
3. 新工程后续样式检查首次错误地比较了未由项目设置的 html 默认字体。实际正文/控件、CSS 字节已一致；将断言修正为项目 token 与实际有样式的元素后，重新执行取消增量的九项检查通过。原失败记录保留在本地，没有改产品实现。原始错误栈含机器目录，未进入公开汇总。

实现者与主执行者分别承担模块检查和真实浏览器检查，另由非作者交叉审查新工程两阶段与老工程最终产物。审查针对实际代码/差异及指纹证据，不以作者总结代替验证，也没有再跑一套相同浏览器全量。
